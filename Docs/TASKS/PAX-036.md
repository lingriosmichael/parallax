TITLE: Checkpoints v1: shared checkpoint IDs, live-cat activation, respawn at the current checkpoint
PHASE / GATE: Plan Phase 9 (cheap failure), pulled ahead of networking. Plan tickets end at
PAX-035, so new tickets continue from PAX-036.

OBJECTIVE
A cat that falls respawns immediately at the latest checkpoint for its reality, with that
checkpoint's gravity, no death screen and no scene reload. Checkpoints are shared: reaching one
with either live cat moves both cats' respawn points forward. The world (anchors, Echo, the other
cat) is not rewound.

CONTEXT
- 02_ARCHITECTURE.md §11 (CheckpointSnapshot, restore is instant, no reload), §3.1 (Systems holds
  CheckpointManager), §6 (only SetTargetDirection/snap changes gravity), §8.5 (overlap queries on
  Stepped), D-003 (checkpoints owned by the session authority), D-028 (sensor policy).
- Existing: CatRespawn.RespawnAt(position, gravityDirection) snaps gravity, sets body and transform
  position, calls motor.ResetMotion. FallResetVolume triggers it. `FallResetTest` objects exist in
  both RealityRoots.
- Handoff debt: "respawn must reset anchor states" applies to irreversible (hostile) anchors. None
  exist yet (vine and plate are reversible), so full world restore is deferred (see D-030).

DESIGN (record as D-030)
- Checkpoint IDs are shared integers. Each reality has at most one `CheckpointMarker` per ID; its
  transform is that reality's spawn point for the ID, with a gravity direction.
- A marker activates its ID when **that reality's cat, driven LocalHuman**, overlaps the marker's
  zone. Echo and Inactive cats never activate checkpoints.
- Progress only moves forward: activating a lower or equal ID does nothing.
- Respawn uses, for that Observer, the marker with the highest ID ≤ current that exists in its
  reality. ID 0 is placed at each cat's starting position and is required.
- Falling respawns only the fallen cat. Anchors, sensors, Echo and the other cat are untouched.
- Fall-reset volumes ignore cats driven by EchoReplay (the ghost follows its recording).

  ### D-030 · <date> · Accepted
  **Decision:** (1) Checkpoints use shared integer IDs with at most one marker per ID per reality; a marker's transform and gravity define that reality's spawn. (2) Only a LocalHuman cat overlapping a marker activates it, on `ObserverSet.Stepped`; progress only advances. (3) A fall respawns only the fallen cat, at the highest-ID marker ≤ current in its reality, with that gravity snapped; anchors, sensors, Echo and the other cat are untouched. (4) Fall resets ignore EchoReplay cats.
  **Why:** Cheap failure (Vision pillar 3): falling costs a moment, not the partner's progress. Current anchors are reversible, so the world can't be left unsolvable. Echo is a ghost of a recording and must not be yanked out of it.
  **Consequence:** A full snapshot restore (§11: both cats, anchors with presenter snap, cancel Echo, clear pending transport items, resync toggles and sensor latches) is required before the first irreversible anchor or reconnect support. In co-op (PAX-033), activation becomes a request to the session authority.
