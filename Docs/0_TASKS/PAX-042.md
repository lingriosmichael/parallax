## 1. Goal

Give level design its first five troll traps, so PAX-043 can build rooms of the form
*setup → obvious route → betrayal → learned solution*:

1. **Collapsing floor** — solid until touched, then drops out after a short delay.
2. **Hidden spikes** — invisible and harmless until triggered, then lethal.
3. **Falling block** — released by a trigger, travels up or down, kills on contact, lands solid.
4. **Door that moves away** — the room's door slides to a new spot when the cat gets close.
5. **Gravity-flip trap** — a trigger zone that flips (or forces) the cat's gravity.

Every trap is deterministic, tick-driven, resets with the room (D-041), and is readable in greybox.

## 2. Rules every trap follows

1. **Ticked by `RoomManager` only.** Traps implement the existing `RoomTrap` contract and run in
   the *live traps* phase. No trap subscribes to `ObserverSet.Stepped`, uses `Update`,
   `FixedUpdate`, coroutines, `Time.time`, or physics trigger callbacks.
2. **Timing is in ticks.** Delays and durations are integer tick counts. Motion is a pure function
   of *ticks since start* (no accumulated floats, no velocity integration). Same inputs, same tick
   → same result.
3. **Only the `LocalHuman` cat triggers.** Detection is an `OverlapBox` on the trap's own reality
   layer mask, counting a cat only when its Observer's driver is `LocalHuman`. `Inactive` and
   `EchoReplay` cats never trigger traps (consistent with the PAX-041 `RoomDeath` rule).
4. **Overlap boxes use `BoxCollider2D.bounds`** (centre and size), never
   `transform.position + box.size`. This respects offset and scale (PAX-041 carry note).
5. **Kills go through `RoomDeath`** with the existing hazard/contact cause. No new death path, no
   new `DeathCause` values in this ticket.
6. **Reset restores authored state exactly**: positions, collider enabled state, renderer state,
   countdown state, armed flags. Reset goes through `RoomResetRegistry` like `DebugTrap`.
7. **Only the current room is live** (D-050). A trap in a non-current room neither ticks nor
   triggers.
8. **No anchors.** No trap in kit v1 reads or writes an anchor. The PAX-041 question "should
   presenters snap or animate toward reset anchor values" stays open until the first anchor-using
   trap (§9).
9. **Gravity changes only via `GravityReceiver.SetTargetDirection`** (CLAUDE.md). Never touch
   `Physics2D.gravity`.

## 3. Pure logic (`Parallax.Core`)

Small, allocation-free, EditMode-tested. Place next to the existing room/checkpoint types.

### 3.1 `TrapCountdown`
State machine `Armed → Counting → Fired`.

- `Step(bool triggered)` → returns `true` only on the tick it fires.
- `Armed` + `triggered` → starts counting. With `delayTicks == 0` it fires on that same tick.
- Once `Counting`, it no longer needs the trigger (touch-and-leave still fires).
- `Fired` stays fired until `Reset()`.
- Optional `rearmOnExit`: after firing, returns to `Armed` on the first tick with
  `triggered == false`. (Used by the gravity-flip trap; default off everywhere else.)
- `TicksSinceFired` is available for motion.

### 3.2 `TrapMotion`
- `Progress(int ticks, int durationTicks)` → `float` in [0, 1], clamped; `durationTicks <= 0`
  returns 1.
- `Travel(int ticks, float unitsPerTick, float distance)` → `min(ticks × unitsPerTick, distance)`,
  never negative.

### 3.3 `GravityFlipRule`
- `Resolve(mode, current)` with modes `Flip`, `ForceUp`, `ForceDown` → target direction, using
  the project's existing up/down gravity representation (D-037, D-048).

## 4. Traps (`Parallax.Gameplay`)

One MonoBehaviour per trap, next to `RoomTrap`. Each has a child `Trigger` object holding a
`BoxCollider2D` (isTrigger = true, used only for its bounds) unless stated otherwise. Per-instance
serialized fields are level data; defaults below assume the 50 Hz fixed step. **If the project's
fixed step is not 0.02 s, keep the tick values and report it.**

### 4.1 `CollapsingFloorTrap`
- Solid platform (`BoxCollider2D`, not trigger) on the reality's geometry layer.
- Trigger = the platform's own bounds expanded by `touchSkin` (default 0.05) on all sides; a
  separate `Trigger` child is not needed.
- Fields: `delayTicks` (default 12 ≈ 0.24 s), `touchSkin`.
- On fire: disable the solid collider and the renderer. (No fall animation in v1.)
- Reset: collider and renderer enabled, countdown reset.

### 4.2 `HiddenSpikesTrap`
- Owns one `Hazard` (reuse the PAX-041 component; do not write a second hazard).
- Fields: `revealDelayTicks` (default 0).
- Before firing: hazard **disarmed** (never kills) and renderer hidden.
- On fire: hazard armed, renderer shown.
- **Same-tick kill is intended:** traps run before hazards (A1 order), so spikes that reveal under
  the cat kill on that tick. Requires §5.1 (per-phase snapshot) and §5.2 (armed flag).
- Reset: disarmed and hidden.

### 4.3 `FallingBlockTrap`
- A block with a kinematic `Rigidbody2D` + solid `BoxCollider2D` on the geometry layer, plus a
  `Trigger` child.
- Fields: `direction` (`Down` | `Up`, world axis, independent of the cat's gravity),
  `delayTicks` (default 0), `unitsPerTick` (default 0.3 ≈ 15 u/s), `travelDistance` (authored;
  where it lands).
- On fire, each tick: position = start + direction × `TrapMotion.Travel(TicksSinceFired, …)`,
  applied with `Rigidbody2D.MovePosition`.
- **Lethal only while moving:** while travel < distance, an overlap of the block's `bounds`
  (shrunk by 0.02 on each side so standing beside it is safe) with the `LocalHuman` cat kills via
  `RoomDeath`. After landing it is plain solid geometry.
- Reset: back to start position (set position directly, not `MovePosition`), countdown reset.

### 4.4 `DoorRetreatTrap`
- References the room's existing door root (PAX-040). Does **not** change door completion logic.
- Fields: `offset` (local Vector2 the door moves by), `moveTicks` (default 10), `delayTicks`
  (default 0).
- On fire: door root position = start + offset × `TrapMotion.Progress(TicksSinceFired, moveTicks)`.
  The door's `Art` child (PAX-A05) moves with it.
- Because traps run before the door phase, a door that starts moving on the tick the cat would
  have entered it is **not** entered on that tick. Intended.
- Verify the door phase reads the zone's **current** bounds. If it caches a position, stop and
  report.
- Reset: door back to start.
- Level-design note (not enforced here): the retreated door must still respect the room skip rule
  (D-050).

### 4.5 `GravityFlipTrap`
- Fields: `mode` (`Flip` default | `ForceUp` | `ForceDown`), `delayTicks` (default 0),
  `rearmOnExit` (default **false** = once per room life).
- On fire: `GravityFlipRule.Resolve` → `GravityReceiver.SetTargetDirection` on the triggering cat.
- Reset: countdown only. The cat's gravity is restored by the respawn path (D-032: snapped to the
  checkpoint's stored direction). Confirm this in acceptance step 6.

## 5. Changes to existing code (PAX-041 carry notes)

### 5.1 `RoomManager` — snapshot per phase
Copy each list into a reusable buffer **immediately before its phase** (traps, then hazards), and
iterate the buffer. Enabling or disabling a trap/hazard during a phase must not skip or double-tick
anything. Taking the hazard snapshot *after* the trap phase is what lets §4.2 kill on the reveal
tick. No per-tick allocations.

### 5.2 `Hazard` — bounds and armed flag
- Overlap box from `box.bounds` (rule 4).
- Add `Armed` (serialized, default **true**, so existing hazards behave exactly as before) plus
  `SetArmed(bool)`. A disarmed hazard stays registered but never kills.
- Reset does **not** change `Armed`; the owning trap resets it.

### 5.3 `DeathInfo.AnchorsReset`
Count only anchors whose reset request was actually sent (skip unregistered ones). The debug
panel line format stays the same.

### Not changed
`DebugTrap` (sandbox only, stays in `DebugTools`, never used in real rooms), the unreachable
room/checkpoint mismatch check in `RoomDeath` (harmless, leave it), presenters, anchors, co-op
code (frozen, D-047).

## 6. Setup menu — `PARALLAX/Setup/Trap Kit (PAX-042)`

Idempotent Editor script, same style as `Hazards and Room Reset (PAX-041)`.

- Creates one instance of each trap under a `Traps_PAX042` parent in Reality A, registered to the
  room it sits in. Greybox via `SetupUtility.SetVisual`:
  collapsing floor = sand/tan, spikes = red (hidden until fired), falling block = dark grey,
  gravity-flip zone = translucent purple (zone visible, it is a test object).
  The door-retreat trap attaches to the existing `Door_0` with an offset that keeps it reachable.
- **Placement:** inspect the scene read-only first (existing hazards at x = 1.5 and 6.5,
  `DebugTrap_0` at x = −2, `Door_0` at x = 3, the ledges after the shrink commit). Put each trap on
  free, reachable ground, not overlapping existing objects. **List the chosen positions in the
  output.** If there isn't room for all five in the sandbox, stop and report rather than moving
  existing objects.
- Creates only missing objects; never rewrites an existing child's settings (known limitation:
  delete and rerun to change one).
- Agents do not edit scene YAML; the developer runs the menu and saves (Cmd+S).

## 9. Proposed decision (Architect records after review)

**D-051 · Trap kit v1 semantics** *(number to be confirmed against `07_DECISIONS.md`)*
Traps are ticked only by `RoomManager` in the live-traps phase, time in integer ticks, move as pure
functions of ticks since firing, trigger only on the `LocalHuman` cat via own-reality overlap
queries, kill only through `RoomDeath`, and restore authored state on room reset. Traps fire once
per room life unless explicitly re-armable. Kit v1 uses no anchors; presenter snap-vs-animate on
reset is decided with the first anchor-using trap.

## 11. Acceptance (Editor)

1. **Collapsing floor:** step on it → it disappears after ~¼ s and the cat falls. Touch it and
   jump off immediately → it still disappears.
2. **Hidden spikes:** invisible and harmless before the trigger; enter the trigger → spikes appear.
   Standing on their spot when they appear → death on that tick.
3. **Falling block:** trigger → block travels and kills the cat if hit; once landed, the cat can
   stand on it and walk beside it without dying.
4. **Door retreat:** approach `Door_0` → it slides away with its art; reach it at the new spot →
   room completes as before.
5. **Gravity flip:** enter the zone → gravity flips instantly (D-048); movement stays
   screen-relative (D-049); zone does not fire again until the room resets.
6. **Reset:** fire all five, then die. Every trap is back in its authored state (floor solid,
   spikes hidden and harmless, block and door at start, flip zone armed), gravity equals the
   checkpoint's direction, and the panel shows `reset 5+ traps` with the correct anchor count
   (§5.3).
7. **Determinism:** the same route with the same input timing produces the same outcome twice.
8. **Inactive cat (Tab):** switch away while the cat stands in a trigger → nothing fires.
9. **Regression:** PAX-041 hazards, `DebugTrap_0`, doors and room completion behave as before.
10. Console: zero new warnings or errors across the whole run.
