# PAX-064 · Audio: mixer, ambient bed, cues, volume wiring

**Status:** Built 2026-10-20 (D-158), awaiting the developer's Editor steps (§8). The draft below is kept; §8 records what was built and where it differs.
**Phase:** Solo v1, Phase F
**Depends on:** PAX-054 (settings), all trap kits (PAX-055/056/058)
**Decisions:** Vision §9, D-062 (7), D-064
**Implementer reads first:** trap base class and fire points, `RoomDeath` (`Died`, kill),
`CatRespawn`, door completion, `GameSettings`/`SettingsStore`.

---

## 1. Why

Every betrayal should be heard as well as seen (Vision §9). Volumes are already stored
(PAX-054) and need wiring.

## 2. What to build

1. **Single trap-fire event:** if traps don't already raise one, add `TrapFired(trapId, kind,
   worldPos, tick)` to the trap base, raised once at the fire tick (D-055 (1) definition). This
   event is also what PAX-065 uses.
2. **`AudioMixer`** asset with groups Music, Sfx, UI; exposed volume params. Settings 0–1 map to
   dB with `20·log10(v)`, and 0 → −80 dB.
3. **`AudioCueBank`** (`ScriptableObject`): one slot per cue: per trap kind fire, death, respawn,
   door/level complete, jump, land, flip, UI tap/back. Each slot: clip(s), volume, pitch jitter
   range (presentation only; never affects gameplay), max simultaneous.
4. **`GameAudio`** (`Parallax.Gameplay`, wired by the composition root, no singleton): listens to
   the events above, plays cues through pooled `AudioSource`s; ambient bed loop per level (bed
   chosen in `LevelLayout` data, default one bed for all). Pausing (PAX-054) pauses Sfx, keeps a
   ducked bed.
5. Missing clip → silent, logged once per slot. Audio never gates gameplay timing.
6. Clips are provided by the developer (licence recorded in `Docs/Audio/Licences/`); import
   settings: bed streaming/Vorbis, short Sfx decompress-on-load.

## 3. Rules

No new packages (built-in Unity audio only) · audio is presentation: removing `GameAudio` must
not change any test · no `Time.time`-driven gameplay.

## 4. Tests (EditMode)

1. Each trap kind raises `TrapFired` exactly once at its fire tick (chained, periodic, rearm).
2. Volume mapping: 1 → 0 dB, 0.5 → ≈ −6 dB, 0 → −80 dB.
3. Cue dispatch maps each event to its slot (fake player, no real audio).
4. Max-simultaneous limit respected.

## 5. Allowed files

Trap base file (event only), new files under `Core`, `Gameplay`, `Data`, `Audio`, `Editor/Setup`,
`Tests/EditMode`, level template setup script.

## 6. Out of scope

Music composition · adaptive music · haptics (PAX-065).

## 7. YOU — UNITY EDITOR

Run All; play three levels with headphones: every trap fire has a cue, death/respawn are short,
sliders work live and persist. Mix on a phone speaker is **unverified (Phase H)**.

## 8. Required output

As `CLAUDE.md`, review file `pax064_review.txt`. Commit: `PAX-064: audio`.

## 8. As built (D-158, 2026-10-20)

The developer: "Do it in code. I trust you. Do this next." The sounds are synthesized; no clips or licences are needed.

**Differences from the draft:**
- **§2.2: no `AudioMixer` asset.** Unity has no public API to make one from an Editor script, and `.asset` files aren't
  hand-edited. Music, Sfx and UI volumes live in `AudioCueBank`, applied per voice. `AudioCues.ToDecibels` keeps the
  mapping for a later mixer.
- **§2.6: synthesized, not provided.** The sounds come from `SfxPresets`, rendered by `SfxSynth`. A recording in the bank
  replaces any one of them.
- **No volume UI.** PAX-054 stored no volumes, so there was nothing to wire.
- **Cues are fixed.** No pitch jitter: repeats walk a fixed pitch pattern.

**Files:**
- **Core** (`Assets/_Game/Core/Audio/`):
  - `AudioCue.cs`: cues, channels, `CueSpec`, the death-kind map, dB, the pitch walk.
  - `CueLimiter.cs`
  - `SfxSynth.cs`
  - `AmbientBed.cs`
  - `SfxPresets.cs`: the sound designs.
- **Gameplay** (`Assets/_Game/Gameplay/Audio/`): `AudioCueBank.cs`, `GameAudio.cs`, `LevelAudioEvents.cs`, `TrapCues.cs`.
- **Trap fire event:**
  - `RoomTrap.cs`: `Fired` and `RaiseFired`, raised from `StepTiming`.
  - `GravityFlipTrap.cs`: the rearm-on-exit countdown raises it too.
- **Editor:**
  - `Editor/Setup/AudioSetup.cs`: the menu `PARALLAX/Setup/Audio (PAX-064)`.
  - `Editor/Setup/TitleSetup.cs`: the title gets `GameAudio` too.
- **Tests:** `SfxSynthTests.cs`, `TrapFiredEventTests.cs`, `AudioSetupTests.cs`.
- **Docs:** this ticket, `07_DECISIONS.md` D-158, and `08_V1_ROADMAP.md`.

**Tests (§4):**
- §4.1 is `TrapFiredEventTests`, through the shared timing path:
  - once per fire, on the fire tick;
  - again after a rearm;
  - never on a reset;
  - a throwing listener is logged.
- §4.2 is `Volumes_MapToDecibels`.
- §4.3 is `EachTrapKind_HasItsOwnCue` and `EachDeathKind_HasItsCue`.
- §4.4 is `TheLimiter_CapsVoices_AndSpacesStarts`.
- Added:
  - every cue renders at its peak, without clicks, deterministically;
  - the bed loops without a seam;
  - the setup is idempotent and the saved scenes are wired;
  - a woken `GameAudio` builds every cue and plays one.

## 9. YOU — UNITY EDITOR (as built)

1. Save the open scene.
2. Run **`PARALLAX/Setup/Audio (PAX-064)`**. It creates `Assets/_Game/Data/AudioCueBank.asset`, then adds and saves
   `GameAudio` in `_LevelTemplate`, `Title` and `LevelSelect`.
3. Run **`PARALLAX/Setup/Levels/Rebuild All Levels`**.
4. If you run `PARALLAX/Setup/Title Screen` again later, it keeps the audio.
5. Play the title, then L001–L003, with headphones:
   - the bed fades in;
   - every trap fire has a sound;
   - jumps and landings sound;
   - death and respawn are short;
   - level complete chimes;
   - buttons click, including the ones that change scene;
   - pause ducks the bed.
6. Tune the mix if needed: the volumes in `AudioCueBank`, and a per-cue override to trim, mute or replace a sound.
7. The mix on a phone speaker is unverified (Phase H).
