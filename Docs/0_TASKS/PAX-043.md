## 1. Goal

Build the first playable solo level: **four greybox troll rooms** in a new scene, using only the
PAX-042 trap kit, the PAX-041 hazard, and the new cat collider (D-052).

**No tutorial rooms.** Players of the genre already know the deal. Every room is a real troll room
from the start. Rooms mix traps and **stack betrayals**, so the obvious fix for the first trap walks
you into the second. "Learned" means learned by dying.

This is the first real level content, and it proves the traps' timings and sizes against the new
collider before trap art (PAX-A06/A07) locks them in. Sizes and timings are expected to change
during acceptance.

**No new gameplay code.** Rooms are data: scene objects created by a setup menu and tuned by the
developer in the Inspector. If a room needs behaviour the code doesn't have, stop and report.

## 4. Rooms

All rooms are in Reality A, under `RealityRoot_A/Rooms_PAX043/Room_N`. Coordinates are **local to
the room origin**, and the origins are at x = 0, 40, 80, 120 (y = 0). Wide spacing plus the door
teleport makes the skip rule (D-050) hold by construction: no room's checkpoint can be reached
from another room.

**Frame for every room:**
- Floor top at y = 0, 1 u thick.
- Ceiling underside at y = 7, 1 u thick.
- Walls at x = 0 and x = W, from y = −4 to 8. No room has a way out except its door.
- The checkpoint is at x = 2, gravity **down**. Its root marker sits at
  `y = floorTop − CatMotorConfig.ColliderBottom`, which is **floor top + 0.4**, read from config and
  never typed as 0.4.
- **Room ids equal checkpoint ids: Room 1 → 0, Room 2 → 1, Room 3 → 2, Room 4 → 3.**
- **Level start:** as built, `CheckpointProgress.Current` starts at 0 and play starts at the cat's
  authored position. The setup menu therefore places the **Cat A root on Room 1's checkpoint
  marker**. That is the one existing object the menu may change, and it only sets the position if
  it differs. No start-behaviour code change.
- **Pits:** a gap in the floor with a solid bottom at y = −3, covered by a `Hazard` strip
  (0.3 tall) across the full width of the pit.

**Disguise rule (greybox):**
- **Betrayals are disguised.** Collapsing sections use the colour of the surface they're part of
  (floor, ledge or ceiling). The falling block uses the ground's colour. Hidden spikes are hidden
  until they fire. A flip zone used as a betrayal has no renderer.
- **Tools are visible.** A flip zone the player must use stays translucent purple.
- **Visible hazards stay red.**

Timings are ticks at 50 Hz and use the D-051 semantics. All coordinates are starting points; the
Architect rescales them at the §2 gate once R is known.

### Room 1 · "Chase" (W = 24): door retreat → collapsing floor
| Element | Placement | Settings |
|---|---|---|
| Floor | x 0–14 and x 17–24 | |
| Pit | x 14–17 | Hazard strip at the bottom |
| `CollapsingFloorTrap` | x 14–17, flush with the floor | `delayTicks` 12, ground colour |
| Door | starts at x 10 | → Room 2 |

- **Obvious route:** walk to the door, which is right there.
- **Betrayal 1:** the door slides away to x 20.
- **Betrayal 2:** chasing it at full speed runs you over the collapsing section into the pit.
- **Solution:** jump the 3 u section.

### Room 2 · "High road" (W = 24): static spikes → hidden spikes → collapsing ledge
| Element | Placement | Settings |
|---|---|---|
| Floor | x 0–24 | |
| Static `Hazard` | x 8–9 on the floor | red, visible |
| `HiddenSpikesTrap` | x 10–14 on the floor | `revealDelayTicks` 0 |
| Its trigger | x 7.5–9.5, y 0–4 (the air above the static spikes) | |
| Step | x 3–5, top at y 2 | |
| Ledge, solid part | x 6–8, y 4–4.5 | |
| Ledge, `CollapsingFloorTrap` | x 8–12, y 4–4.5 | `delayTicks` 12, ledge colour |
| Door | x 21 | → Room 3 |

- **Obvious route:** hop over the red spikes.
- **Betrayal 1:** the hop fires the trigger, and the landing zone becomes spikes.
- **Obvious fix:** take the ledge over the spikes.
- **Betrayal 2:** the ledge drops out halfway, and the cat falls into the spikes.
- **Solution:** jump from the end of the solid part (x 8) and land past x 14. The cat stays above
  the trigger the whole time.
- **No soft-lock:** after the ledge collapses, the solid part is still reachable from the step.

### Room 3 · "Over the top" (W = 24): falling block → hidden gravity flip
| Element | Placement | Settings |
|---|---|---|
| Floor | x 0–24 | |
| `FallingBlockTrap` | 1.5 × 1.5 block at x 11–12.5, hanging from the ceiling (y 5.5–7) | `direction` Down, `travelDistance` 5.5, `unitsPerTick` 0.3, `delayTicks` 3, ground colour |
| Its trigger | x 8–8.5, **y 0–7** | |
| `GravityFlipTrap` (hidden) | x 14–17, y 0–2 (floor level) | `mode` ForceUp, `rearmOnExit` false, no renderer |
| Ceiling `Hazard` | x 13–24 on the ceiling underside (all the way to the wall) | red |
| Door | x 21 | → Room 4 |

- **Obvious route:** run right.
- **Betrayal 1:** the block drops as the cat arrives under it.
- **Obvious fix:** bait it, let it land, and jump over it.
- **Betrayal 2:** a jump from the floor lands the cat in the hidden zone, which throws it up into
  the ceiling spikes.
- **Solution:** hop onto the block, then jump from its top to land past x 17.
- The ceiling spikes run to the wall on purpose: a cat flipped anywhere past x 13 always dies. It
  can never end up alive on the ceiling with the door on the floor.
- **Tune `delayTicks`** until a full-speed run dies and stop-and-wait survives.

| Element | Placement | Settings |
|---|---|---|
| Floor | x 0–24 | |

- **Betrayal 1:** the door escapes to the ceiling.
- **Obvious fix:** use the purple zone and walk along the ceiling.
- **Betrayal 2:** the ceiling gives way over the recess, and the cat falls up into the spikes.
- **Solution:** jump the 3 u section on the ceiling.
- The door trigger is full height, so flipping first also works. With `rearmOnExit`, a jump back

## 5. Setup menu — `PARALLAX/Setup/Solo Rooms (PAX-043)`

Idempotent Editor script, in the same style as `Trap Kit (PAX-042)`.

- **Refuses to run** unless the active scene is `Level_Solo01`, and logs an error saying so.
- **Layout data** goes in a plain static class, `SoloRoomsLayout` (Editor): one record per
  element, following the §4 tables. The menu reads it and the tests check it.
- **Creates only missing objects**, and never rewrites an existing child. It's a one-time
  scaffolder: after it runs, the scene is the source of truth and the developer tunes in the
  Inspector. To rebuild a room, delete `Room_N` and rerun the menu.
- **Creates checkpoints, doors, hazards and traps through the existing setup helpers, generalised**
  (amended at the gate). In `CheckpointSetup`, `RoomSetup`, `HazardSetup` and `TrapKitSetup`,
  each builder becomes a parameterised `internal static` core that takes the parent, the name,
  the position, the size (hazards, traps) and the trap settings. It returns the existing child if
  one with that name is already under the parent, and creates it otherwise. The **old method keeps
  its signature and becomes a one-line wrapper** that calls the core with exactly the values it
  hard-codes today (`RealityRoot_A/Checkpoints`, `Checkpoint_{id}`, 0.5 × 0.3, the sandbox trap
  positions, and so on). All component wiring stays in the core, so there is one place that knows
  how to build each object. The old menus must produce exactly what they produce today. List each
  generalised method and its wrapper.
- **Wires every reference through `SerializedObject`**: find the property, apply, `SetDirty`,
  mark the scene dirty. Every trap guard must pass at Play.
- **Sets room and checkpoint ids explicitly.** No position-based rule like the sandbox's
  `x > 3`.
- **Objects:**
  - Greybox through `SetupUtility.SetVisual`, following the disguise rule.
  - Gameplay objects on `A_Gameplay` at sorting order −2.
  - Every trap trigger must stay clear of the checkpoint's spawn footprint.
- **Output** lists each created object and its world position.

## 10. Proposed decision

**D-053 · Room grammar v1**
- No tutorial or teaching rooms: every solo room is a troll room from the start.
- Rooms stack betrayals: the obvious fix for one trap leads into the next. Players learn by dying.
- Betrayals are disguised as their surroundings; tools the player must use are visible.
- No room can soft-lock: every state is either completable or ends in a death, which resets the
  room (D-041).
- Rooms are physically separate and joined only by door teleports, so the skip rule (D-050) holds
  by construction.
- Rooms are scene data scaffolded by a setup menu and then tuned in the scene; they are not
  gameplay code.

## 11. Acceptance (Editor)

1. **Start:** Play begins in Room 1 at its checkpoint. The cat appears on the floor, with no drop
   and no embedding.
2. **Each room, stacked betrayals:** the obvious route dies to betrayal 1, and the obvious fix
   dies to betrayal 2. After each death the room resets to its authored state and the cat is back
   at the checkpoint.
3. **Each room, solution:** it clears reliably, 3 times in a row.
4. **Room 3 timing:** full speed dies; stop-and-wait survives. Report the final `delayTicks`.
5. **Soft-locks:** in Room 3, a flipped cat always dies. In Room 4, both routes to the door work
   (flip first, or approach first), and flipping back and forth works. In every room, try to get
   stuck, and report any state you can't leave.
6. **Doors:** each door teleports the cat to the next room's checkpoint with gravity down. Report
   whether the camera snaps or pans. Report what the last door does.
7. **Disguise:** no collapsing section, falling block or hidden flip zone can be told apart from
   its surroundings before it fires.
8. **Full run:** Room 1 to the last door in one go. Report the deaths per room on the first blind
   attempt and roughly how hard each room felt.
9. **Determinism:** the same route with the same timing gives the same result twice.
10. **Regression:** in `Sandbox_Realities`, rerun `Checkpoints`, `Rooms`, `Hazards and Room
    Reset (PAX-041)` and `Trap Kit (PAX-042)`. Each reports "already configured" (or its
    equivalent), and `git status` shows no change to the sandbox scene. Then the sandbox still
    plays as before (PAX-041/042 checks 1–6).
11. **Console:** only known noise across the whole run.
