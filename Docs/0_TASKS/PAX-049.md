## 1. Why

The last door of `Level_Solo01` only logs "Level complete": a player finishes and nothing
happens on screen. The per-room death count exists (`RoomDeath.DeathsIn(roomId)`) but nothing
shows it. Both are needed before the blind playtest (with PAX-037): testers need an ending, and
the playtest measures deaths per room.

## 2. What to build (D-061)

1. **Level-complete screen.** When the level completes, the cat freezes and a plain uGUI screen
   appears: "Level complete", one row per room in level order (`Room 1 — 3 deaths`, rooms with
   0 deaths included), the total, and a **Restart** button. Placeholder look, no art, no
   animation. Inside the safe area, landscape.
2. **Nothing during play.** No death counter on screen, no popup when a single room is cleared.
   A door still moves the cat to the next room on the same tick (D-050).
3. **Restart** reloads the active level scene. Counts reset with it. Nothing is saved.
4. **Stats log.** With the fixed prefix `PARALLAX_STATS`, one line per room clear
   (room number, deaths in that room, ticks since that room became current, hold ticks included)
   and one summary line at level complete (per-room deaths and total). Readable via
   `adb logcat | grep PARALLAX_STATS` on the phone.
5. **Input.** The Restart button implements `ITouchReservedRegion`, so the stick and jump never
   claim a touch that starts on it. In the Editor, Enter also restarts while the screen is shown.
   Before the screen is shown, nothing new reacts to input.

Room number = the room's position in level order, 1-based, not its internal checkpoint id.

## 4. Rules

- **After level complete the room is inert:** the cat is frozen (`CatMotor2D.Freeze`), and no
  trap, hazard, bounds or door phase runs, and no further death is counted. A kill and a last-door
  touch on the same tick still resolve as today: the kill wins, the level does not complete.
- `LevelCompleted` still fires exactly once.
- Pure logic (building the summary rows and total from ordered room ids and `DeathCounter`,
  formatting the stats lines) lives in `Parallax.Core` and is tested there. The screen is a thin
  `Parallax.Gameplay` MonoBehaviour.
- The screen is player-facing: it lives in `Parallax.Gameplay`, not `Parallax.DebugTools`.
- Frozen co-op code stays untouched. `Sandbox_Realities` gets no screen and no change.
- New setup menu `PARALLAX/Setup/Level Complete UI (PAX-049)`: idempotent (find-or-create by
  name, then rewire), and **it refuses to run unless the active scene is `Level_Solo01`**, with a
  logged error naming the open scene. This is the first setup menu with a scene guard.

## 5. Tests (EditMode, required)

Core:
1. Summary rows follow level order and include rooms with 0 deaths; room numbers are 1-based
   positions, not checkpoint ids.
2. Total equals the sum of the rows.
3. The stats lines match the exact format, prefix included.

Gameplay (PAX-047's rig):
4. Touching the last room's door fires `LevelCompleted` exactly once, and the summary built at
   that moment matches the deaths recorded per room.
5. After level complete: stepping further ticks runs no phases, a `Kill` is not counted, and
   the cat is frozen.
6. A kill and the last-door touch on the same tick: the kill wins, the level is not complete,
   the death is counted once.
7. Each room clear logs one `PARALLAX_STATS` line with that room's deaths and ticks
   (`LogAssert.Expect`).

Tests must fail for the right reason before the code exists (e.g. test 5 fails because a kill is
counted, not because a type is missing). No existing test is modified.
