## 1. Goal

PAX-044's kit-gap list named three things the rooms wanted and kit v1 couldn't do:

- **Chaining:** a trap that fires because another trap fired.
- **Moving traps:** spikes that slide, floors that rise, walls that close in and crush.
- **Repeating traps:** traps that fire more than once per room life.

This ticket adds all three to the kit, makes them expressible in layout data (D-054), and proves
them in a **Trap Lab** scene. **No level rooms change.** Using the new kit in `Level_Solo01` is a
later rooms ticket.

## 2. What stays true (D-051, unchanged)

- Traps are ticked only by `RoomManager` in the live-traps phase: traps → hazards → door.
- Time is integer ticks. Motion is a pure function of ticks since firing.
- Only the `LocalHuman` cat triggers traps, via own-reality overlap queries on collider bounds.
- Kills go only through `RoomDeath`.
- Room reset restores authored state (D-041), now including chain, repeat and motion state.

## 3. Decision D-055 (commit before implementation)

```
### D-055 · 2026-09-22 · Accepted
**Decision:** Trap kit v2 (PAX-045).
(1) Trigger source. Every trap fires from exactly one source: Overlap (its own trigger box, as
in v1) or Chain (another trap in the same room firing). A trap "fires" at the tick its effect
starts: trigger tick + delay for Overlap, source fire tick + delay for Chain. A chained trap's
delay is at least 1 tick, so tick-list order never changes the result. Chains are acyclic and
stay inside one room; setup and tests reject cycles and cross-room links.
(2) Repeat mode. Once (v1 default): fires once per room life. Rearm: after firing, the trap
returns to its authored state when its cooldown ends (snap, no return animation in v2) and can
fire again from its trigger source. Periodic: fires every P ticks, counted from room start
(tick 0 of the room life) plus a phase offset; it has no trigger. Motion is a pure function of
ticks since the latest fire.
(3) Moving trap. A new trap moves a body from its authored pose by an offset over M ticks, holds
H ticks, and optionally returns over R ticks. Kind Hazard: kills on overlap, tested against its
pose computed for that tick, not physics state. Kind Solid: kinematic geometry moved with
MovePosition; a cat whose collider overlaps the solid's tick pose shrunk by crushDepth on every
side dies through RoomDeath (a crush).
(4) Room reset restores every trap's authored pose, arming, chain state and repeat counters.
**Amends:** D-051's "fire once per room life unless explicitly re-armable": repeat mode is the
explicit mechanism. `GravityFlipTrap`'s existing `rearmOnExit` stays as is.
**Why:** Level Devil rooms mutate as you solve them. Chains, moving and repeating traps are the
three gaps PAX-044 found; defining them on ticks keeps every room deterministic and learnable
(D-040, D-050).
```

## 5. Design

Shape it to the as-built kit. The intent:

- **Timing is pure and shared.** One small pure class (e.g. `TrapTiming`, in `Parallax.Core` or
  `Parallax.Gameplay`, whichever the traps already use for tick maths) answers, for a trap's
  settings and the ticks it has seen: has it fired, the latest fire tick, ticks since that fire,
  and whether it is armed. Every trap uses it; no trap re-implements delay, cooldown or period.
- **Chaining without order dependence.** A source records its fire tick. A target reads the
  source's latest fire tick and fires at `sourceFire + delay` (delay ≥ 1). Because the target
  only acts on ticks after the source fired, the order the room ticks them in cannot matter. A
  test proves it by ticking the same room in both orders.
- **Rearmed sources chain again.** Each new fire of the source can fire the target again, if the
  target is armed (target's own repeat mode decides).
- **`MovingTrap`:** pose(t) is piecewise linear: authored → authored + offset over M ticks, hold
  H, back over R ticks (R = 0 means it stays). The Hazard kind kills when the cat's collider
  bounds overlap pose(t) in the hazard phase. The Solid kind drives a kinematic `Rigidbody2D` with
  `MovePosition(pose(t))` and checks crush in the same phase. Both kinds work in either gravity.
- **Crush** default depth 0.15 u, from a config asset, not a literal.
- **Reset** returns everything to authored state on the reset tick, including kinematic bodies.
- **Tunables** (default crush depth, any new defaults) go in a ScriptableObject under
  `Assets/_Game/Data` (CLAUDE.md). Per-trap values come from layout data.

  outside `Sandbox_TrapLab`.
- **Three lab rooms**, W 32, same frame as PAX-044, each with a checkpoint and a door:
  1. **Chain:** at least one three-link chain, including a door retreat as the last link, and one
     domino of three falling blocks each chained to the previous one.
  2. **Move:** sliding spikes (Hazard), a rising floor that pushes the cat into ceiling hazard
     (Solid), and a closing wall that crushes a cat against fixed geometry (Solid, crush).
  3. **Repeat:** periodic spikes in a rhythm the cat can walk through with timing, a rearming
     falling block, and a rearming collapse.
- Every feature shows **a kill case and a survive case**, each written down in the Phase 1 table.

## 8. Tests (EditMode)

Pure-logic tests, no scene needed:

1. **Timing:** Once, Rearm and Periodic fire ticks for given settings, including phase and the
   first tick after cooldown.
2. **Chain order independence:** the same source/target pair ticked in both list orders gives the
   same fire ticks.
3. **Chain delay ≥ 1** is enforced.
4. **Cycles and cross-room links are rejected** (layout validation).
5. **Moving pose** is a pure function: pose(t) at 0, mid-move, end of move, hold, mid-return,
   end; R = 0 stays.
6. **Crush:** a collider touching the solid's edge survives; one overlapping the shrunk rect dies.
7. **Reset** returns timing state to authored (armed, no fire tick).
8. **Layout data:** every Trap Lab trap declares its settings in layout data (rule 7); chained and
   periodic traps have no trigger box; every chain source exists in the same room.
9. **Regression:** `Level_Solo01` layout data unchanged (all PAX-044 layout tests still green).

**Baseline:** 241 (PAX-044). Report baseline → new.

## 13. Acceptance (Editor)

1. **Every kill case kills and every survive case survives**, 3 times each, as in the Phase 1
   table.
2. **Chains** fire in the stated order and ticks. The domino reads as a domino.
3. **Moving:** sliding spikes kill on contact; the rising floor carries the cat up and the ceiling
   hazard kills; the closing wall crushes against fixed geometry and does not crush a cat that
   only touches it. No cat is pushed through geometry.
4. **Repeat:** periodic spikes keep their rhythm across deaths (the room reset restarts the
   rhythm at phase); rearming block and collapse come back and fire again.
5. **Reset:** dying mid-chain, mid-move and mid-cycle restores the room completely.
6. **Gravity up:** a moving Solid and a moving Hazard behave the same for a ceiling walker.
7. **Determinism:** the same inputs give the same result twice.
8. **Regression:** `Level_Solo01` plays as before; `Sandbox_Realities` menus report no change.
9. **Console:** known noise only.
