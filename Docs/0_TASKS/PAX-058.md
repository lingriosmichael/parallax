# PAX-058 · Bounded randomness: seeded trap variants

**Status:** Dropped by D-067 (2026-09-25): no randomness in v1. Kept for reference only; do not implement.
**Phase:** Solo v1, Phase C
**Depends on:** PAX-057
**Decisions:** D-062 (3) Luck guardrails, D-057, D-059 (`DeathCounter`), D-064; new **D-066**
(randomness as built)
**Implementer reads first:** D-062 (3), `DeathCounter`, `LevelStatsLog`, trap reset
(`IRoomResettable`), the layout validators and `TierRulesConfig`.

---

## 1. Why

Hard levels may use luck, but only inside D-062's guardrails: randomness picks between authored
variants, every variant is survivable and visible in time, and every death can be replayed.

## 2. What to build

1. **`VariantGroup`** (layout data): a named set of 2–4 **authored alternatives** of trap
   settings in one room (e.g. launcher on left vs right; which of 3 floor tiles collapses). Each
   alternative is a full, ordinary trap configuration. Randomness never touches timing, speed or
   hitbox size (only which alternative is live).
2. **Choice:** at the start of each room life (level load and every reset), each group picks one
   alternative. Inactive alternatives are fully disabled (no trigger, no kill, hidden or shown
   as plain geometry per data).
3. **Seed:** `seed = Mix(FNV1a64(levelId), attempt)` where `attempt` = deaths in this level
   session + 1. PRNG is a small pure one in `Parallax.Core` (SplitMix64). **Not**
   `UnityEngine.Random` or `System.Random`, so results are identical in Editor and IL2CPP.
   Group order is the data order, so adding a group at the end doesn't change earlier picks.
4. **Log:** each room life logs `level`, `attempt`, `seed`, and the chosen index per group,
   through the existing `LevelStatsLog` path (release builds included; one line per attempt).
5. **Replay:** a dev-only (`defineConstraints`, `Parallax.DebugTools`) seed override: enter a
   seed/attempt, the next room life uses it.
6. **Telegraph:** the chosen alternative must be visible ≥ D-057's lead before it can kill,
   using that trap's own reveal; the validator checks each alternative separately.
7. **Validation:** every alternative, on its own, passes the level's tier rules; Novice levels
   with any `VariantGroup` fail validation.

## 3. Rules

No wall-clock or frame-rate input to the seed · no randomness outside `VariantGroup` · same seed
+ same inputs ⇒ same room, tick for tick.

## 4. Tests (EditMode)

1. Same level id + attempt ⇒ same choices, across repeated runs and after a domain reload.
2. Choice distribution over 10,000 attempts is roughly uniform (each within ±5%).
3. Reset re-picks with attempt+1; replaying a logged seed reproduces the choice.
4. Inactive alternatives never trigger or kill.
5. Validator: an alternative that fails tier rules, or has lead < 6, fails the level; a Novice
   level with a group fails.
6. Known-answer test pinning SplitMix64 and FNV-1a outputs (guards IL2CPP/Editor parity).

## 5. Allowed files

New files under `Core`, `Gameplay`, `DebugTools`, `Editor/Setup`, `Tests/EditMode`; layout
element/builder/validator files; `LevelStatsLog.cs` (log line).

## 6. Out of scope

Random timing/speed (forbidden by D-062) · daily seeds · analytics upload.
