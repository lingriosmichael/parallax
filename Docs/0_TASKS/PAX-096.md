# PAX-096 · PAX-A13 follow-up: inverter cue frame order, stable Trap Lab room order

**Status:** Draft (opened by PAX-A13's Done handover, 2026-09-30); needs the Architect's approval before work starts.
**Phase 1 size: Lite.**
**Depends on:** PAX-A13 (Done). **Decisions:** D-099 (Proposed: presentation reads state, never writes it).

## 1. Why

PAX-A13's final pass found two small issues. Neither blocks play; both were left out of the art-only Done commit.

1. **The inverter's cue can lag the cat by a frame.** `InverterTrap` moves its grey-box cue (the ring and the mark) onto
   the cat in `LateUpdate`. `InverterArt` mirrors that grey-box, also in `LateUpdate`, and Unity doesn't order the two,
   so the art can draw the cue where the cat was last frame. It's the only trap that moves a grey-box in `LateUpdate`.
   (The contact sheet shows the cue at the orb, not on the cat, for a different reason: the route harness never calls
   `LateUpdate`. That's a sheet limit, not a game bug.)
2. **Rebuilding the Trap Lab can reorder its rooms.** Seen after PAX-A13's final bodies: the saved `Sandbox_TrapLab`
   went from `Room_1 … Room_13` to `Room_4 Room_1 Room_2 Room_3 Room_5 … Room_13` under `RealityRoot_A/Rooms_PAX045`.
   Nothing reads rooms by child order (they're found by name), so the change was accepted, but it makes the scene diff
   noisy and the order depends on history.

## 2. What was checked (2026-09-30, on the batch clone)

- **Running the Trap Lab setup twice gives the same order.** Starting from the reordered scene, run 1, run 2, and a reopen
  all left `Room_4 Room_1 Room_2 Room_3 Room_5 … Room_13`.
- **The cause is the rebuild path, not a random order.** Starting from the committed scene (`Room_1 … Room_13`), one run of
  `TrapLabSetup.Configure` rebuilt every room that differed from its layout (after the new art, all but Room_4, which has
  no spikes or cracks) by destroying and recreating it. A recreated room is appended at the end of `Rooms_PAX045`, and
  Room_4, left untouched, ended up first. So the order is stable once rebuilt, but it isn't set: it depends on which
  rooms happened to be rebuilt.

## 3. What to build

1. `[DefaultExecutionOrder]` on `InverterArt` (Presentation), after `InverterTrap`'s default order, so the cue art always
   mirrors this frame's grey-box. Test first: a check that `InverterArt`'s execution order is later than
   `InverterTrap`'s, seen red before the attribute is added.
2. The Trap Lab setup (PAX-045) sets each room's sibling index explicitly, in layout order, after creating or rebuilding
   it, so any rebuild gives `Room_1 … Room_13`. Test first: rebuild the Trap Lab from a scene where one room is recreated,
   and assert the child order matches the layout.

## 4. Allowed files

`Presentation/InverterArt.cs`; `Editor/Setup/TrapLabSetup.cs`; tests. After the change, the developer runs
**PARALLAX → Setup → Trap Lab (PAX-045)** once and saves (the order goes back to `Room_1 … Room_13`).

## 5. Out of scope

Any other trap's art; the route harness calling `LateUpdate`; the level builder (levels have one room each); Reality B.
