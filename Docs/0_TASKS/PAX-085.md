## 1. Why

The developer wants a troll that swaps left and right. D-049 removed accidental reversal (from gravity), and that stays removed. What's new is a **trap**: a thing in the room you touch, after which left and right are swapped for a fixed, visible time. It's deterministic, it teaches in one death, and it's allowed only in levels 11+.

## 2. What to build

1. **Element `Inverter`** (appended to `SoloRoomElementKind`). A box in the room. Trigger: Overlap on its own body (like a collapsing floor), or a separate trigger box, or Chain. Repeat: Once (default) or Rearm. Settings: `DurationTicks` (default **150** = 3 s at 50 Hz).
2. **The effect.** On fire, the LocalHuman cat's horizontal input is negated for `DurationTicks` room ticks: the `Move` the motor receives is `−Move`. Jump is not affected. (KIT-8's climb axis will not be inverted; KIT-8 states it.)
   - Pure `ControlInversion` in `Parallax.Core`: `Fire(tick, duration)`, `IsActive(tick)`, `Remaining(tick)`. Refiring while active **restarts** the full duration (Rearm).
   - Applied in one place, between the router and the motor (Phase 1 names it: most likely `LocalHumanDriver`), so Play and the route harness go through the same code.
   - Counted in room ticks: the death hold (D-059) and pause (D-073) freeze it for free. Room reset and respawn clear it (`IRoomResettable`).
3. **Visible cue (fairness).** For the whole duration the cat shows an inversion cue (a tint plus a small swirl/⇄ mark over the cat; placeholder art). The last 30 ticks blink so the player sees it ending. The cue is a `SpriteRenderer` change so the route validator can see it.
4. **Look.** Honest (a visible orb/pickup, default) or disguised (invisible trigger box, like chained traps, D-056 (4)).
5. **Validator.** `ValidateInverter`: duration 25–500 ticks; `ValidateBand` rejects it in levels 1–10. An inverter's own box is never a kill volume (door clearance ignores it).
6. **Routes.** New pseudo-element `Cat.Inverted` (like `Cat.Gravity`, D-079 (3)) whose first visible change is the fire tick. A betrayal that dies *because* of inversion declares `revealedBy: Cat.Inverted`; lead ≥ 6 as usual. Route conditions gain `Inverted()` if useful. Route moves stay screen-relative *input* (`Hold(Right)` means the stick is pushed right; the cat then moves left while inverted).
7. **Trap Lab room 7:** a corridor with a spike pit. An orb just before the pit: grab it and your learned "hold right, jump" walks you back into a hazard; the answer is to wait it out (visible timer) or play it inverted. Solution + one Dies betrayal + one Recovers betrayal.

## 4. Rules and stop conditions

- The default mapping stays D-049 screen-relative. No other code path may invert input.
- Frozen co-op/Echo code untouched. If the only place to negate is frozen, stop and report.
- No `Time.time`; ticks only.

- Death hold and pause don't advance the timer; respawn clears it.
- Cue visible from the fire tick to the last active tick; blink in the last 30.
- `ValidateInverter` and `ValidateBand` clauses. Room 7 routes and camera tell rule pass.

## 11. Rulings (Phase 1, 2026-09-26)

**Status:** Ruled. Go to Phase 2. Baseline: the developer's Test Runner total at 2c0cdb9 (expected 805). Where these differ from §2–§6 they amend the ticket.

**Accepted as traced:** the negation goes in `LocalHumanDriver`, on the motor command only, after `SeatCommandFilter` (Q1); pause doesn't clear inversion (Q4); several inverters active at once means the cat is inverted while any one is active. They don't toggle each other. Record it in D-087.

### R1 · Cue: ring plus ⇄ mark, no body tint (open question 1)

Approved for this ticket. The cat prefab and `CatVisualPresenter` stay untouched.
- The cue is the inverter's own child renderers: a ring behind the cat and a ⇄ mark above it (placeholder art). The mark stays upright with gravity up; it doesn't rotate with the cat.
- **On/off is game state:** it's set in the room tick. On from the fire tick through the last inverted motor step, and blinking in the last 30 ticks (on/off, a pure function of the ticks remaining). The route harness sees it.
- **Position is presentation only:** it follows the cat's Transform in `LateUpdate`, so it moves smoothly with the interpolated cat. Nothing in the game or the harness reads it.
- `Cat.Inverted`'s render box for the camera tell rule is the **cat's collider bounds**, not the cue's, so it never depends on the presentation position. Its first visible change is the cue switching on.
- If the ring doesn't read clearly in the developer's §9 play, a follow-up ticket adds an overlay through `CatVisualPresenter`. It's not done here.

### R2 · `RouteReplay.cs` added, for `Cat.Inverted` only (open question 2)

Approved. Add the second extra element next to `Cat.Gravity` (lines 67 and 297–319) and nothing else. Guard, as in PAX-084: every pinned route result must stay **identical**. If one moves, stop and report.

### R3 · The driver finds inverters when it activates (open question 3)

Approved. `IControlModifier { bool InvertsMove { get; } }` in Core, with these conditions:
- Collect with `GetComponentsInChildren<IControlModifier>(true)` under the observer's own reality root in `Activate`, the same way it already finds `CatInteractor` and `CatSeat`. A reality with no inverters (`Sandbox_Realities`, the co-op sandbox) gives an empty list and changes nothing.
- `InvertsMove` is true only while the trap's room is the live room, the death hold isn't running, and the upcoming motor step is inside the inversion window.
- Test: in the route harness **and** in a built Trap Lab room, the driver's list contains the inverter after activation (seen red by removing the lookup). If the harness activates the driver before the room is built, stop and report; don't reorder frozen code.

### R4 · Timing: the window is counted in motor steps

The trap fires in the room step at tick T, after that tick's motor step. So the inverted motor steps are **T+1 through T+DurationTicks**, exactly `DurationTicks` of them (150 by default). Refiring at tick T′ restarts the window at T′+1. The Phase 2 test pins both edges to the tick: the last right-moving step is T, the first left-moving step is T+1, the last inverted step is T+150, and step T+151 moves right again. D-087 states the window this way.
