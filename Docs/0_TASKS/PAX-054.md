## 1. Why

Today the only ways out of a level are dying or reaching the door. v1 needs a pause button that
stops the game and offers Resume, Restart and Levels. On a phone, the game must also pause itself
when the app goes to the background, so the player doesn't come back to a dead cat.

## 2. What to build

### 2.1 Pausing

1. **One pause state per level scene**, owned by a small component (e.g. `LevelPause`) with pure
   logic in `Parallax.Core` (e.g. `PauseState`: `Pause()`, `Resume()`, `IsPaused`; both calls
   idempotent).
2. **While paused, nothing in the level advances:** cat movement and physics, the observer tick,
   traps and their timers, death hold and respawn, and the death counter. Input is ignored. When
   the player resumes, everything continues from exactly where it stopped. Phase 1 decides the
   mechanism (see §3.1).
3. **The pause button can't be used while the level complete screen is showing.** Hide it when
   the complete screen appears.
4. **Auto-pause:** when the app loses focus or goes to the background (`OnApplicationPause(true)`
   or `OnApplicationFocus(false)`), the level pauses and the pause panel is shown. Coming back
   never resumes automatically; the player taps Resume.

### 2.2 Pause UI

1. **A pause button** in a top corner of the HUD, inside a reserved touch region (D-023), so
   tapping it never moves the cat or triggers a jump.
2. **A pause panel** with three buttons: **Resume**, **Restart**, **Levels**. It uses the same
   plain style as the complete screen. No new art, no animation.
3. **Restart** reloads the current level through `LevelSceneLoader`. **Levels** loads
   `LevelSelect` through `LevelSceneLoader`. Neither records progress (D-073).
4. **Resume** hides the panel and unpauses.

### 2.3 Leaving a level always unpauses

`LevelSceneLoader.Load` restores the normal running state (e.g. `Time.timeScale = 1` if Phase 1
chooses time scale) before it loads any scene, so `LevelSelect` and the next level never start
frozen. If the load is refused (the scene isn't in Build Settings), the pause state stays as it
was.

### 2.4 Template-targeted setup

1. New menu `PARALLAX/Setup/Levels/Pause Menu`. It is idempotent, and its guard accepts only
   `_LevelTemplate` (D-070). It builds the pause button, the panel and the wiring.
2. `Level_Solo01` gets no pause menu and is never modified.
3. After running the menu on the template, the developer runs `Rebuild All Levels`.

## 3. Phase 1: trace, then stop

Answer each question with file:line references.

1. **What advances the game.** List everything that moves game state forward in a level scene,
   and what it runs on: `Update`, `FixedUpdate`, the `ObserverSet` tick, coroutines, `Invoke`,
   `Time.time` / `Time.deltaTime` versus unscaled time. Include cat movement, traps, moving
   platforms, death hold, respawn, the death counter and camera follow. Then recommend a
   mechanism with its trade-offs:
   - (a) `Time.timeScale = 0`, if everything that must stop scales with time;
   - (b) an explicit pause flag checked by the tick owner(s);
   - (c) a mix.

   Name every file the chosen mechanism would have to change.
2. **Input.** How touch and keyboard commands reach the cat (`ICatCommandSource`, the input
   router). What does the cat receive on the first tick after resume? Could a held jump or stick
   input "leak" through the pause, e.g. a jump that was latched before pausing?
3. **Reserved regions (D-023).** How HUD buttons are kept out of stick and jump input today, and
   how the complete screen's buttons are registered. What the pause button needs to do the same.
4. **Complete screen.** How `LevelCompleteScreen` is shown, and the hook the pause button can use
   to hide itself. Can the level complete while paused (e.g. a trigger fired on the same frame)?
5. **Death count.** Where the current attempt's death count lives, and confirm that reloading the
   scene through the loader discards it without recording anything.
6. **App lifecycle.** Any existing `OnApplicationPause` or `OnApplicationFocus` handlers, and what
   they do.
7. **Editor behaviour.** In the Editor, focus changes whenever you click another window. Should
   auto-pause be skipped in the Editor (`Application.isEditor`), or only on focus loss and not on
   background? Recommend one.

Stop if an answer needs a file outside §6, touches frozen code, or changes `Level_Solo01.unity`.
Stop also if the mechanism in 3.1 needs changes in more than the files §6 allows; list them and
recommend.

## 5. Tests (EditMode)

1. **Pause state (pure):** `Pause` and `Resume` are idempotent; the state starts unpaused.
2. **Nothing advances while paused:** for each tick owner Phase 1 names, a paused step changes
   nothing (cat position and velocity, trap timers, death-hold timer, death count), and the first
   step after resume continues from the same values.
3. **No input leaks:** a jump latched or a stick held before pausing is not applied on resume.
   What "not applied" means is defined by the Phase 1 answer to 3.2.
4. **Loader unpauses:** after a successful load call the running state is restored; after a
   refused load it is unchanged. Test through the loader's existing seam.
5. **Restart and Levels from pause** load through the loader and record no progress.
6. **Complete screen hides the pause button**, and the pause button can't pause after completion.
7. **Auto-pause:** simulated focus loss or background pauses and shows the panel; regaining focus
   does not resume. Respect the Editor rule chosen in 3.7.
8. **Scenes:** each listed level scene has a pause button in a reserved region and a pause panel
   with Resume, Restart and Levels wired.
9. **Guard:** the Pause Menu setup refuses every scene except `_LevelTemplate`.

Every test must fail before the code exists, for the reason named. No existing test is modified;
new tests may be added to `LevelSceneTests.cs` (additions only).

## 7. D-073 (write as built)

A level can be paused from a HUD button in a reserved touch region, and it pauses itself when the
app goes to the background. While paused, no game state advances and input is ignored; resume
continues exactly where it stopped, with no input carried over from before the pause. The pause
menu offers Resume, Restart and Levels. Restart and Levels abandon the current attempt: nothing
is recorded, and best deaths remains the fewest deaths in one completed run. Every scene load
restores the running state, so no scene starts paused. [Mechanism from Phase 1: time scale, pause
flag, or both.]

## 8. Out of scope

- Settings, audio and volume.
- Android back button.
- Pause art, blur or animation.
- A title or main menu.
- Changing unlock or best-deaths rules.
