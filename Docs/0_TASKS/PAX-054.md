# PAX-054 · Pause menu and settings

**Status:** Approved for implementation once PAX-053 is committed
**Phase:** Solo v1, Phase B
**Depends on:** PAX-053
**Decisions:** D-062 (4), D-064, D-058/D-059 (tick gating), D-049
**Implementer reads first:** `RoomManager.OnStepped` gating, `RoomDeath.IsHolding`,
`CatInputRouter`, `TouchStickCatInput`, `VirtualStick`, `LevelProgressStore`, `MenuNavigation`.

---

## 1. Why

D-062 (4) needs pause (resume, restart, level select) and settings (music and sound volume,
haptics, touch stick size/position). Audio and haptics are built later (PAX-064/065); this
ticket stores their settings so those tickets only wire them.

## 2. What to build

1. **Pause button** (top edge, clear of FLIP, inside the safe area, `ITouchReservedRegion`),
   plus Escape / Android back in a level. Opens the pause panel: **Resume**, **Restart**,
   **Level select**, **Settings**.
2. **Pausing** stops the simulation deterministically: the room tick does not advance, traps and
   the death hold don't step, the cat's body is frozen and input is discarded (same approach as
   the D-058 hold; reuse `CatMotor2D.Freeze/Unfreeze` if the Phase 1 trace confirms it's safe to
   call from outside `RoomDeath`). Do **not** use `Time.timeScale` unless the trace shows the
   tick gate can't do it; if so, stop and report. Resume continues on the next tick with no
   input carried over. App losing focus (`OnApplicationPause(true)`) opens pause.
3. Restart and Level select from pause **record nothing** (only completions are recorded).
4. **`GameSettings`** (`Parallax.Core`, pure): `MusicVolume` and `SfxVolume` (0–1),
   `HapticsEnabled`, `StickScale` (e.g. 0.75–1.5), `StickAnchor` (normalized screen position
   for the left zone's default origin, clamped to the left half). Defaults in a
   `SettingsDefaults` asset.
5. **`SettingsStore`** (`Parallax.Gameplay`): the only `PlayerPrefs` owner for settings,
   separate keys from `LevelProgressStore`, same corrupt-data fallback (defaults + warning).
6. **Settings screen** reachable from title and pause: two volume sliders (stored only, no sound
   yet), haptics toggle (stored only), stick size slider and a "move stick" mode where the
   player drags a preview; **Reset to defaults**. Changes apply live and save on close.
7. `TouchStickCatInput` reads `StickScale`/`StickAnchor` at enable and on a settings-changed
   event. Floating-origin behaviour is unchanged; only the size and default origin change.

## 3. Phase 1 — as-built trace

1. Is gating the room tick + `Freeze` enough to stop everything that moves (moving traps use
   `MovePosition` on ticks; anything on `Update`/`Time.time`)?
2. What stick parameters exist today and where are they configured?
3. Where would a settings-changed event best live without a new singleton?

## 4. Rules

- Pause never changes simulation results: a room paused on tick N resumes at tick N identically.
- No audio or haptics code (PAX-064/065). No new packages.
- `SettingsStore` and `LevelProgressStore` never share keys.

## 5. Tests (EditMode)

1. Pausing at room tick N and resuming after K frames: `RoomLifeTick` is N+1 on the next step,
   trap states match an unpaused run at the same tick.
2. Input given while paused has no effect after resume (jump latch cleared).
3. Pausing during a death hold: the hold resumes with the same ticks left.
4. Restart / Level select from pause record nothing in `LevelProgress`.
5. `SettingsStore` round-trip; corrupt data → defaults without throwing.
6. `StickScale` and `StickAnchor` are clamped to their ranges.

## 6. Allowed files

New files under `Core`, `Gameplay`, `Data`, `Editor/Setup`, `Tests/EditMode`;
`TouchStickCatInput.cs`, `CatMotor2D.cs` (only if Freeze needs a public entry, report it),
`RoomManager.cs` (pause gate only), the PAX-053 menu setup and level template setup scripts.

## 7. Out of scope

Sound, haptics · language setting · control remapping · cloud save.
