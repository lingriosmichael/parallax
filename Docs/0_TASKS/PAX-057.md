# PAX-057 · Difficulty tiers and provisional hard-tier rules

**Status:** Draft. Architect refreshes after PAX-056 is committed.
**Phase:** Solo v1, Phase C
**Depends on:** PAX-056
**Decisions:** D-062 (3), D-064 (2), D-056, D-057; new **D-065** (provisional hard-tier numbers)
**Implementer reads first:** the layout validators, where 12 ticks and 0.75 reach are defined,
`LevelListConfig`, the PAX-051 all-levels fixture.

---

## 1. Why

Levels 11–50 are allowed tighter timing and jumps than D-056 (D-062 (3) Execution). The real
numbers need the phone (D-064 moved that to Phase H), so this ticket sets **provisional**
numbers now and makes changing them later a one-asset edit whose effect the tests list.

## 2. What to build

1. **`DifficultyTier`** enum (`Novice`, `Hard`) on each `LevelListConfig` entry. L001–L010
   Novice, L011+ Hard (enforced by a test once those levels exist).
2. **`TierRulesConfig`** assets under `Assets/_Game/Data`: `Novice.asset` (slack 12 ticks,
   max jump 0.75 reach, lead 6 ticks, i.e. D-056/D-057 as today) and `Hard.asset`
   (**provisional D-065**: slack 8 ticks, max jump 0.85 reach, lead 6 ticks).
3. Validators take a `TierRulesConfig` instead of constants. The literal 12 / 0.75 / 6 disappear
   from code; the old tests keep passing because Novice holds the same values.
4. **Margin report:** the all-levels fixture prints, per level, the tightest slack and the
   largest jump fraction actually used and which element uses it. Phase H's retune (PAX-069)
   reads this report to see which levels a stricter number would break.
5. D-065 text: the provisional numbers, that they came from the Editor only, and that PAX-069
   replaces them.

## 3. Rules

Novice behaviour and results are unchanged · one source for each number (the asset) · no new
trap behaviour here.

## 4. Tests (EditMode)

1. Novice asset values equal the pre-ticket constants (guards against drift).
2. A layout with 10-tick slack fails Novice and passes Hard; 7 ticks fails both.
3. A 0.8-reach jump fails Novice and passes Hard.
4. Each listed level is validated against its own tier's asset.
5. The margin report lists every level with non-empty values.

## 5. Allowed files

Validator files, `LevelListConfig.cs`, new files under `Core`, `Gameplay`, `Data`,
`Tests/EditMode`.

## 6. Out of scope

Randomness (PAX-058) · designing hard levels · device numbers (PAX-069).
