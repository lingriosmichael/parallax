## 1. Observed

In Editor play of `Level_Solo01` after PAX-047, **room 3's exit door sits on top of a trap**:
reaching the door kills the cat. Found by the designer during PAX-047 acceptance; the death
hold is what made it legible.

Room 3 (ceiling room) as built in PAX-046: collapse (moved, room 1's spot is now solid) →
Flip_A → Periodic rising block (P 96, cooldown 48) on the ceiling route → CeilingSpikes (Once)
→ Retreat → Flip_B.

PAX-047 changed no layout, but it added a kill path: out-of-bounds (D-058 (2)). So it is not yet
known whether a hazard kills the cat at the door or the route there leaves the room's bounds.
§2 decides.

**Observed by the designer before Phase 1:** _what the hold showed at the kill: ______ ·
`OutOfBounds` warning naming room 3 in the console: yes / no_

## 2. Phase 1 — diagnose before changing anything

Post the answer, then wait. Which case this is decides the fix; one of the cases is not a bug.

1. **Which element overlaps the door?** From `SoloRoomsLayout`'s room 3 data, list every
   element whose AABB intersects the Door element's AABB, and the overlap in units. Check every
   pose **and the swept volume between poses**: CeilingSpikes' armed volume, the Periodic
   block's travel and raised pose, the door's travel during the Retreat and its destination. Say
   which way gravity points when the cat reaches the door (Flip_A / Flip_B state).
2. **Which of these is it?**
   - (a) A trap's kill volume overlaps the door's own footprint: the cat dies on arrival.
   - (b) The kill comes with less than D-057's 6-tick visible lead on the route to the door:
     a real learnability bug.
   - (c) The Retreat moves the door onto the CeilingSpikes: working as authored, and a design
     question, not a defect. Still report the D-057 lead in ticks for this kill.
   - (d) The kill is `OutOfBounds`: on the route to or through the door (e.g. a flip or launch
     near the exit) the cat's collider centre leaves room 3's baked bounds. Per D-058 (2) this is
     a layout hole. Report the trajectory (start, apex, bounds edge) in units.
3. **Does any existing test cover this?** `SoloRoomsLayoutTests` has D-057 lead tests and
   distinct-openings tests. Say why none of them caught it — that gap matters more than the
   room itself, because the same hole would let it recur in the real rooms.
4. **Is room 1, 2 or 4 affected the same way?** Run the same overlap check on all four rooms
   and report.

5. If the data allows more than one case, say so and name the check that would separate them.
   Do not guess from the observed note alone.

Do not change layout data or tests in Phase 1.

## 3. Fix, once the case is known

- **(a), (b) or (d):** a layout fix in `SoloRoomsLayout.BuildCeilingRoom` only — move the trap, the
  door, or the trap's timing so the door is reachable; for (d), close the hole so the cat stays
  inside the room's bounds. Keep the room's four betrayals and its
  ceiling route; do not soften it into a safe room. Report the numbers before and after.
- **(c):** no code change. Report it and stop; the designer decides whether room 3 keeps the
  behaviour.

Any fix must keep the room passing every existing rooms-v3 test (D-056: 12-tick slack from
rest, platform jumps ≤ 0.75 reach, clear sweeps and launches, disguise, learnability) and
D-057's 6-tick lead.

## 4. New test (required for (a), (b) and (d), and worth it either way)

A **general** test, not a test of this one room — the PAX-046 lesson was that tests of named
openings miss what tests of every case catch:

> For every room in `SoloRoomsLayout` and `TrapLabLayout`, the Door element's footprint (and,
> where a DoorRetreat exists, its retreated footprint) does not intersect any hazard volume,
> in any pose or the swept volume between poses, in any armed state, in either gravity.

If a room legitimately needs a trap near its door, the test should encode what "near" is
allowed to mean (e.g. a clearance in units) rather than exempting the room.

If the case is (d), also propose in Phase 1 a general test that would have caught it (for example:
every flip zone's or launch's resulting trajectory stays inside its room's bounds). Describe
its semantics and wait for approval before writing it.
