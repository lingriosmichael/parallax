TASK: PAX-040
TITLE: Room model v1 (solo): a room is a checkpoint and a door; touching the door completes it
PHASE / GATE: Pivot, solo (D-040, D-047). Follows PAX-039.

OBJECTIVE
A room starts at a checkpoint and ends at a door. When the solo cat touches the current room's
door, the room is complete and the cat appears at the next room's checkpoint on the same tick.
When there is no next room, the level is complete.

CONTEXT
- D-040 (room = checkpoint + door, deterministic), D-047 (solo only; solo features take an
  ObserverId, never hard-code A; the two-reality sandbox must keep working), D-030 / PAX-036
  (checkpoint ids, markers, CheckpointManager, advance-only progress), D-048 (vertical gravity).
- 02_ARCHITECTURE.md §3.1 (RealityRoot hierarchy, Systems), §8.5 (overlap queries on Stepped),
  §11 (checkpoints as built).
- Existing: CheckpointManager (`Current`, `Activate(id)`, `Respawn(observer)`, `Activated`),
  CheckpointMarker (overlap pattern), CheckpointPolicy, ObserverSet.Stepped, CatRespawn.RespawnAt.
- Not in this ticket: hazards and room reset (PAX-041, D-041), death counter or lives (D-044 still
  Proposed), co-op rooms (D-047).

DESIGN (record as D-050)
- **Room id = checkpoint id.** Room N starts at checkpoint N. A room is the `RoomDoor` with id N
  plus the checkpoint markers with id N. No separate room object.
- **Solo reality.** `RoomManager` has a serialized `ObserverId soloReality` (A in the sandbox).
  Only doors in that reality exist for play; a door in another reality is a validation error.
- **Only the current room is live:** the door with id == `CheckpointManager.Current` is checked;
  all others are ignored.
- **Touch completes.** On a tick where the solo cat overlaps the current door and its driver is
  LocalHuman, room N completes, once. Then, on the same tick:
  - if a door with id N+1 exists: `CheckpointManager.Activate(N+1)`, then
    `CheckpointManager.Respawn(soloObserver)`; the cat appears at checkpoint N+1 with that
    marker's gravity;
  - otherwise: the level is complete. Log `Level complete`, raise `LevelCompleted`, stop checking.
- One `ObserverSet.Stepped` handler (RoomManager) does the door query, so order is deterministic.
- Local only. No transport.

- 07_DECISIONS.md: append
  ### D-050 · <date> · Accepted
  **Decision:** (1) A room's id is its checkpoint id; a room is its `RoomDoor` plus the checkpoint markers with that id. (2) Solo rooms live in one reality, set on `RoomManager.soloReality`; doors elsewhere are invalid. (3) Only the current room (`CheckpointManager.Current`) is evaluated. (4) A LocalHuman touch completes the room once; on the same tick the cat is respawned at checkpoint N+1, or, with no door N+1, the level completes.
  **Why:** D-040 defines a room as a checkpoint and a door. Reusing checkpoint ids gives rooms progress and respawn for free. Completing on touch with an instant move keeps the troll loop fast.
  **Consequence:** Walking into a later room's checkpoint marker skips the current room, so level design keeps room N+1's marker unreachable before room N's door. Co-op rooms (doors in two realities) are designed in the co-op update.
