## 1. Why

The level-complete screen (PAX-049) only offers Restart. There is no way to move to a next level,
and nothing survives a restart or app relaunch. D-063 defines the shape: a level is one room, an
ordered data list of levels drives "next level," and per-level unlock state and best death count
persist on the device. Phase B needs this before level-select or any real content can be built.

## 2. What to build (D-063)

1. **`LevelListConfig`** (`Parallax.Gameplay`, `ScriptableObject`, `Assets/_Game/Data`): an
   ordered array of level entries — `Id` (string, stable), `SceneName` (string, matches a scene
   in Build Settings), `DisplayName` (string, for later UI). One asset, one source of truth for
   level order — no other code hardcodes it.
2. **Seed data:** the asset ships with exactly one entry, `Level_Solo01`, since that's the only
   scene that exists. Adding real levels is later content work, not this ticket.
3. **`LevelProgress`** (`Parallax.Core`, pure, mirrors `RoomProgress`'s style): given the ordered
   level ids and a completion record, exposes `IsUnlocked(id)`, `BestDeaths(id)` (-1 = never
   completed), and `RecordCompletion(id, deaths)`, which keeps the minimum death count and
   unlocks the next id in order. The first level is always unlocked. No `UnityEngine` dependency.
4. **`LevelProgressStore`** (`Parallax.Gameplay`): the only place that touches `PlayerPrefs`.
   Loads a `LevelProgress` at startup (or an empty one, seeding the first level unlocked, if
   nothing is saved yet), and saves it back after `RecordCompletion`. Key format and encoding are
   the implementer's call; document it in the file's header comment. Corrupt or missing data
   never throws — fall back to an empty, first-level-unlocked state and log a warning.
5. **`LevelCompleteScreen` gets a Next level button**, alongside Restart, mirroring
   `RestartButton`'s pattern exactly (`ITouchReservedRegion`, same Enter-key convention in the
   Editor — Restart keeps Enter; Next level gets no keyboard shortcut, to avoid a double-binding
   on Enter). It is shown only when `LevelListConfig` has a next entry after the current scene's
   level id; otherwise hidden (today: always hidden, since there is only one entry). Clicking it
   calls `LevelProgress.RecordCompletion` for the just-finished level (deaths = the summary's
   total from PAX-049's `LevelSummary`), saves via `LevelProgressStore`, then
   `SceneManager.LoadScene` on the next entry's `SceneName`.
6. **Restart is unchanged**: still reloads the active scene, still records nothing.
7. **Which level is "current"** is resolved by matching `SceneManager.GetActiveScene().name`
   against `LevelListConfig` entries. If the active scene isn't in the list (e.g. `Sandbox_Realities`,
   `Sandbox_TrapLab`), the Next level button stays hidden and nothing is recorded — this is not an
   error, just an unlisted scene.

## 4. Rules

- `Parallax.Core` stays pure: `LevelProgress` has no `UnityEngine` or `PlayerPrefs` reference.
  Persistence is entirely in the `Parallax.Gameplay` adapter (D-063 (4)).
- `LevelListConfig` is a tunable data asset under `Assets/_Game/Data`, per `CLAUDE.md`'s
  ScriptableObject-config rule — no magic level list in code.
- The Next level button, like Restart, must not let the stick or jump claim a touch that starts
  on it, and must not appear before the level-complete screen is shown.
- No level-select, pause or settings screen — out of scope (D-063 (5)).
- Frozen co-op code stays untouched. `Sandbox_Realities` gets no changes.
- New/changed setup menu (if any UI wiring is needed) follows the existing
  `PARALLAX/Setup/…` idempotent pattern and the `Level_Solo01`-only scene guard `LevelCompleteUISetup`
  already uses — extend that menu rather than adding a second one, unless it must run in a
  different scene context.

## 5. Tests (EditMode, required)

Core:
1. `LevelProgress`: the first level is unlocked with no save data; a later level is locked until
   the one before it completes.
2. `RecordCompletion` keeps the **minimum** death count across repeated completions of the same
   level (e.g. 5 deaths then 2 deaths → best is 2; 2 then 5 → best stays 2).
3. `RecordCompletion` unlocks exactly the next id in order and no other.
4. `BestDeaths` for a level never completed returns the documented "never completed" sentinel.

Gameplay:
5. With a `LevelListConfig` of one entry, the Next level button is hidden when the level-complete
   screen shows (matches today's real content).
6. With a fake two-entry `LevelListConfig` (extend PAX-049's rig; do not load a second real
   scene), the Next level button is shown on level complete and calls `LevelProgress.RecordCompletion`
   with the correct id and death count when clicked.
7. `LevelProgressStore` round-trips through `PlayerPrefs`: save, clear the in-memory instance,
   load, and the unlock/best-deaths state matches.
8. Corrupt/missing `PlayerPrefs` data loads as the empty, first-level-unlocked state without
   throwing.

Tests must fail for the right reason before the code exists. No existing test is modified.
