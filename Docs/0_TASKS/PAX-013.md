# PAX-013 — Touch input → `CatCommand`

**Phase:** 2 — One ugly cat (final ticket before Gate 2)
**Test scope:** Editor **and device** (Pixel 8a)
**Depends on:** PAX-007, PAX-008, PAX-012
**Reviewer pass required:** No (no networking, no shared state)

---

## CONTEXT

`02_ARCHITECTURE.md` §5.1: touch and keyboard both produce `CatCommand`, both implement
`ICatCommandSource`, and the motor never reads input devices directly.

Two constraints shape this ticket:

1. **Keyboard must keep working in the Editor.** You test in Play mode far more often than
   on the phone. Touch must be added *alongside* keyboard, not instead of it.
2. **Edge events must survive the Update/FixedUpdate mismatch.** Touches are detected in
   `Update`; the motor consumes commands in `FixedUpdate`. At 60 fps render and 50 Hz physics
   these do not line up, so a naive `JumpPressed` flag will occasionally be missed entirely
   or read twice. The fix is latch-and-clear-on-read, specified below. This is the single
   most likely source of "sometimes my jump doesn't register" at Gate 2.

**Layout decision (mine, since you didn't have a preference):** a **dedicated jump zone**,
not tap-anywhere-on-the-right-half. Tap-anywhere is more forgiving today, but Phase 3 adds
an interact button and the SWITCH/RECORD buttons, and they all want the right side of the
screen. Reserving that space now costs one evening of thumb-tuning; reclaiming it later
costs a relearned control scheme. All zone rectangles are serialized, so you can widen the
jump zone to the full right half on the device in thirty seconds if you disagree once you
feel it.

### `ICatCommandSource` (Parallax.Core)

```csharp
public interface ICatCommandSource
{
    /// Returns the command for this tick. Implementations MUST clear latched
    /// press-edges (JumpPressed, InteractPressed) as part of this call, so a
    /// single physical press is reported exactly once.
    CatCommand Read();
}
```

### `TouchZones` (Parallax.Core — pure, no UnityEngine dependency beyond `Rect`/`Vector2`)

```csharp
public enum TouchZone : byte { None, MoveLeft, MoveRight, Jump }

public static class TouchZones
{
    /// `point` and the zone rects are in normalised safe-area coordinates (0..1).
    /// Tested in priority order: Jump, MoveLeft, MoveRight. Returns None if no hit.
    public static TouchZone Classify(Vector2 point, Rect moveLeft, Rect moveRight, Rect jump);

    /// Converts a pixel position to normalised coordinates within `safeArea`.
    /// Values outside the safe area are returned outside 0..1, not clamped.
    public static Vector2 ToSafeAreaNormalised(Vector2 screenPoint, Rect safeArea);
}
```

Normalised safe-area coordinates, not raw pixels, so the layout is resolution-independent
and the Pixel 8a's camera cutout does not shift the zones.

### `TouchCatInput` (Parallax.Gameplay)

Uses `UnityEngine.InputSystem.EnhancedTouch`. **No `.inputactions` asset** — that is a
serialised file, and per D-012 we do not hand-author those. Enable with
`EnhancedTouchSupport.Enable()` in `OnEnable` and disable in `OnDisable`.

Serialized fields (all rects in normalised safe-area coordinates, `x,y` = bottom-left):

| Field | Default | Notes |
|---|---|---|
| `Rect moveLeftZone` | `(0.00, 0.00, 0.16, 0.45)` | Bottom-left corner. |
| `Rect moveRightZone` | `(0.16, 0.00, 0.16, 0.45)` | Directly right of it, no gap. |
| `Rect jumpZone` | `(0.78, 0.00, 0.22, 0.45)` | Bottom-right corner. |
| `bool showDebugOverlay` | `true` | Development builds and Editor only. |

Behaviour:

- **Multi-touch is required.** Track active touches by finger ID. Holding left while
  tapping jump must produce `Move = -1` and `JumpPressed = true` on the same tick.
- A touch is classified **once, on the frame it begins**, and keeps that zone until it
  ends. Sliding a thumb from the left zone into the jump zone does not re-trigger.
- `Move` is digital: `-1`, `0`, or `+1`. If both move zones are held, the **most recently
  pressed** wins. Do not sum them to zero — that feels broken.
- `JumpHeld` is true while any finger is down in the jump zone.
- `JumpPressed` is **latched** when a finger begins in the jump zone, and cleared only when
  `Read()` is called. A press occurring between two `FixedUpdate` calls must survive to the
  next one.
- `InteractPressed` / `InteractHeld`: leave as `false`. Interact arrives in Phase 4.
- Debug overlay: `OnGUI`, wrapped in `#if UNITY_EDITOR || DEVELOPMENT_BUILD`, drawing the
  three zones as translucent rectangles that highlight while held. This is how you tune
  thumb positions on the phone — do not skip it.

### `CatInputRouter` (Parallax.Gameplay)

`MonoBehaviour, ICatCommandSource`. Holds a serialized array of `MonoBehaviour` sources,
validated as `ICatCommandSource` in `Awake` (log an error and skip any that are not).

`Read()` calls `Read()` on **every** source exactly once per tick — never early-out, or the
unread source's latched edges leak into a later tick — and merges:

- `Move`: the value with the largest absolute magnitude; ties go to the first source.
- All booleans: logical OR.

This is what lets keyboard and touch coexist in the Editor, and it is what
`LocalHumanDriver` will consume in PAX-014.

### `TouchInputSetup` (Editor)

## ACCEPTANCE TEST

**Editor (1–4):**

1. A/D moves, Space jumps. Keyboard is unchanged.
2. With mouse-touch simulation on, clicking the left zone moves the cat left.
3. Zone gizmos appear in the overlay and highlight when held.
4. EditMode tests: 22 or more pass, zero fail.

**Device — Pixel 8a (5–11):**

5. Hold left: the cat moves left and keeps moving. Release: it stops.
6. **Hold left and tap jump simultaneously.** The cat jumps while still moving left.
   *(This is the multi-touch test. If it fails, finger-ID tracking is wrong.)*
7. Tap jump twenty times in a row. Every tap produces a jump. *(This is the latching test.
   Intermittent misses mean the edge is being cleared before `FixedUpdate` reads it.)*
8. Tap jump just before landing. The buffered jump from PAX-008 fires on touchdown.
9. Run off a ledge and tap jump within the coyote window. The cat jumps.
10. Slide a thumb from the left zone into the jump zone. **No jump fires.**
11. Rotate gravity, walk on a wall: left/right still move the cat along its own surface,
    even though that is now vertical on screen. *(D-020 — confirm this is tolerable.
    Your verdict here decides whether Q-2 stays resolved.)*

12. No Console or logcat errors in any of the above.
