# PAX-114 · Path platforms and glitch walls (D-187 (1), (2))

**Status:** Approved 2026-10-24. The developer picked these mechanics after playing the redo round: "new ways in which the
platforms move ... the walls move different and reposition themselves like a glitch in the matrix".
**Phase 1 size:** Lite. This extends `MovingTrap`'s offset to a list of points, on the same timing, snapshot and kill paths.
**Decisions:** D-055, D-056 (3), D-091, D-095, D-140, D-187.

## 1. What to build

1. **Path mover.** A `MovingTrap` can follow a list of points (offsets from home) instead of one offset.
   - It moves along the polyline at constant speed (by arc length) over `moveTicks`, holds `holdTicks`, and retraces over
     `returnTicks`.
   - A path whose last point is home is a closed loop. On a Periodic beat it circles forever.
   - Carry, push, crush partner and slams work as on any mover.
2. **Glitch mode.** A path mover that teleports instead of sliding.
   - It stays on a point, then jumps to the next, evenly spaced over `moveTicks` (and back over `returnTicks`).
   - For `warnTicks` (≥ 6) before each jump it flickers, and a ghost shows where it will appear.
   - It never carries a rider across a jump, so a cat standing on it falls.
   - A solid that appears on a cat crushes it; a Hazard kills.
3. **Builder:** `PathSettings(points, glitch, warnTicks)`, two-parameter shape. The ghost is a child "<name>_Ghost".
4. **Validator:**
   - Every leg's swept box, or for a glitch wall every pose, overlaps no fixed solid.
   - A glitch step (`moveTicks / points`, and the same on the return) is longer than its warning.
   - The warning is ≥ 6 ticks.
   - Kill volumes, room bounds and arrow crossings use the whole path.
5. **Tests:** path math, glitch index and warning, validator rules, and a runtime rig for the teleport kill and the rider drop.
