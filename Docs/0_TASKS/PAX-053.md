# PAX-053 · Menu scene: title screen and level select

**Status:** Approved for implementation once PAX-051 is committed
**Phase:** Solo v1, Phase B
**Depends on:** PAX-050, PAX-051
**Decisions:** D-062 (4) Flow, D-063, D-064, D-044 (per-room death count)
**Implementer reads first:** `LevelListConfig`, `LevelProgress`, `LevelProgressStore`,
`LevelCompleteScreen`, `RestartButton`, `ITouchReservedRegion`, `LevelCompleteUISetup`.

---

## 1. Why

The game has no front door. Players need to start the game, pick an unlocked level and see
their best death count per level (D-062 (4)).

## 2. What to build

1. **Scene `Menu`** (`Assets/_Game/Scenes/Menu.unity`), created by
   `PARALLAX/Setup/Menu/Build Menu Scene`, placed **first** in Build Settings (this ticket
   permits that one change).
2. **Title screen:** game title (text placeholder until PAX-A09), **Play** (opens level select
   scrolled to the highest unlocked level), **Settings** (disabled placeholder until PAX-054).
3. **Level select:** a grid built at runtime from `LevelListConfig` (never a hand-placed
   button per level). Each cell shows the level number, best deaths (`BestDeaths`, "–" when -1),
   and a locked state from `IsUnlocked`. Tapping an unlocked cell loads its scene. Locked cells
   do nothing. Must work for 4 levels today and 50 later without layout changes (scrolling
   grid).
4. **Back paths:** Android back button / Escape on level select → title; on title → no-op
   (leaving the app is the OS's job). `LevelCompleteScreen` gets a **Level select** button that
   records the completion exactly like Next level does (reuse, don't duplicate) and loads `Menu`
   straight into level select.
5. **`MenuNavigation`** (`Parallax.Gameplay`): the single place scene names for the menu live
   (read from a `MenuConfig` asset, not string literals spread across code), plus a static
   "open at level select" handoff flag set before loading `Menu`.
6. **Safe area:** all menu and level-complete UI sits inside `Screen.safeArea` via one reusable
   `SafeAreaFitter` component.
7. **Editor convenience:** entering Play mode in a `Level_NNN` scene still starts that level
   directly (no forced jump to `Menu`).

## 4. Rules

- Level order, names and lock state come only from `LevelListConfig` + `LevelProgress`.
- No new singletons; `LevelProgressStore` is loaded where PAX-050 loads it.
- Touches on menu buttons never reach gameplay (`ITouchReservedRegion` wherever a level scene
  shows a button).
- No pause, settings content, audio, IAP locks (PAX-054/064/066).

## 5. Tests (EditMode)

1. Level select builds one cell per `LevelListConfig` entry, in order (fake 3- and 50-entry
   configs).
2. Cell state: first unlocked, rest locked with no save; after `RecordCompletion(L001, 3)`,
   L002 unlocked and L001 shows 3.
3. Tapping a locked cell requests no scene load; tapping an unlocked one requests its
   `SceneName` (through an injectable scene loader, no real load).
4. Level-complete **Level select** records the completion with the same id and deaths as Next
   level would.
5. `SafeAreaFitter` maps a given safe rect to anchors correctly (pure math extracted to Core).

## 6. Allowed files

New files under `Core`, `Gameplay`, `Data`, `Editor/Setup`, `Tests/EditMode`;
`LevelCompleteScreen.cs`, `LevelCompleteUISetup.cs`; `Menu.unity` via menu only; level scenes via
`Rebuild All Levels` only.

## 7. Out of scope

Pause, settings (PAX-054) · final UI art (PAX-A09) · transitions/animations · audio · lock icons
for paid levels (PAX-066).
