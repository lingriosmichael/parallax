# PAX-066 · Paid unlock (Unity IAP), locked levels, restore

**Status:** Built 2026-10-31 on a batch clone (D-279); the developer's menus, Play Console setup and a real-billing test are pending (§9, §10). The draft below is kept; §9 records what was built and where it differs. The draft's "D-067" is D-068 (numbering note, PAX-075).

**Depends on:** PAX-053 (level select), Phase D content complete
**Decisions:** D-062 (5), D-067, D-064
**Implementer reads first:** `LevelProgress`, `LevelProgressStore`, level select, `CLAUDE.md`

## 1. Why

Free download with a one-time paid unlock, no ads, no consumables (D-062 (5)).

## 2. What to build

1. **Package:** Unity IAP (`com.unity.purchasing`), the version current for Unity 6000.3 at
   pre-flight; name the exact version in the output. Its API changed between majors: use the
   current one, not tutorials for older versions.
2. **One non-consumable product** `full_unlock` (id in an `IapConfig` asset; the price itself is
   set in Play Console, not in code).
3. **`Entitlements`** (`Parallax.Core`, pure): `IsPaidUnlocked`; `IsPlayable(levelId)` =
   free-set membership (from `LevelListConfig`: `Free` flag per entry, filled per D-067) or paid
   unlock. Combines with `LevelProgress.IsUnlocked`: a level is enterable when progress-unlocked
   **and** playable.
4. **`IapService`** (`Parallax.Gameplay`): initializes the store at startup, buys, restores,
   caches the entitlement locally (so offline play works) and re-confirms from the store on each
   launch when online. Store failure never blocks free levels.
5. **UI:** paid levels show a lock badge in level select; tapping one opens an unlock panel with
   the store's localized price string, **Unlock**, **Restore purchase**. The level after the
   last free one shows the panel from level complete's Next level instead of loading. Restore
   also in Settings.
6. Editor: Unity IAP's fake store for all flows (success, cancel, failure, restore).

## 3. Rules

No ads, no consumables, no analytics · the entitlement cache can only ever grant what the store
granted; clearing data then restoring must recover it · free levels never depend on the store.

## 4. Tests (EditMode)

1. `IsPlayable` for free/paid × locked/unlocked combinations.
2. Purchase success grants; cancel/failure grants nothing and leaves UI usable.
3. Restore with an owned product grants; with none, grants nothing.
4. Corrupt entitlement cache → not unlocked, store re-checked, no throw.
5. `LevelListConfig` free set equals D-067's list.

## 5. Allowed files

`Packages/manifest.json` (Unity IAP only, after approval), new files under `Core`, `Gameplay`,
`Data`, `Editor/Setup`, `Tests/EditMode`, `LevelListConfig.cs`, level select and level-complete
scripts, the menu setup script.

## 6. Out of scope

iOS StoreKit (Phase I) · receipt server validation · promo codes · real-billing test (needs a
Play track, Phase H).

## 7. YOU — UNITY EDITOR

Run All; fake-store: buy, cancel, fail, restore; paid levels lock/unlock correctly; relaunch
keeps the unlock. Real Google Play Billing is **unverified (Phase H)**.

## 8. Required output

As `CLAUDE.md`, review file `pax066_review.txt`. Commit: `PAX-066: paid unlock`.

## 9. As built (D-279, 2026-10-31)

The developer approved `com.unity.purchasing` 5.3.1 and answered D-068's open points (D-279).

**Differences from the draft:**
- **The 12-hour wait is in.** The draft had only the payment, while D-068 says pay **or** wait. `Entitlements` handles both. A wait begins as the
  player leaves the level before it, runs with the app closed, and uses the phone's clock; moving the clock forward skips it, which D-279 accepts.
- **§2.3:** `LevelListConfig.FreeLevels` (10), not a `Free` flag per entry: D-068 is "the first ten", and a count needs no asset rewrite.
- **§2.5:** Settings doesn't exist, so Restore is on the unlock panel and the pause menu.
- **§2.6: not Unity's fake store in the Editor.** Its dialog builds a legacy-input EventSystem that throws every frame in this Input System project,
  so it can't be clicked. `EditorStoreGateway` answers instead, as `IapConfig`'s Editor Store fields say. The Editor never touches Unity IAP.
- **Restore is `FetchPurchases`:** `RestoreTransactions` is refused on platforms that don't override it. iOS (Phase I) needs the real call.
- **Allowed list grew by** `Parallax.Gameplay.asmdef` (the two package references), `PausePanel`, `PauseMenuSetup` and `LevelProgressStore`.
- **Not run:** `Packages/packages-lock.json` is left for Unity to write on the first open. `CLAUDE.md`'s "no IAP" scope line wasn't changed.

## 10. YOU — UNITY EDITOR (as built)

1. Open the project and let Unity install the package (this writes `Packages/packages-lock.json`).
2. Save the open scene. Run, in order: `PARALLAX/Setup/Audio (PAX-064)`, `PARALLAX/Setup/Haptics (PAX-065)`, **`PARALLAX/Setup/Paid Unlock (PAX-066)`**, then
   `PARALLAX/Setup/Levels/Rebuild All Levels`.
3. **Editor:** set `IapConfig`'s Editor Purchase to each of Succeed, Cancel, Fail, Defer and StoreDown, and try level select's L011 and Next level on L010. Tick Editor Owned
   and press Restore. The wait is `waitHours`; a small value such as 0.01 (36 s) shows it opening.
4. **To re-lock while testing,** delete `PARALLAX_FULL_UNLOCK` from PlayerPrefs: Unlock writes it, and it's real saved data in the Editor too.

**Play Console, before a real purchase (Phase H):** create the one-time product `full_unlock`, priced 4.99 with regional prices. Real Google Play Billing is **unverified**.
