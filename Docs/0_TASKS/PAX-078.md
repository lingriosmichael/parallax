## 1. Why

PAX-077 found two rooms that are only fair under the old 60 Hz arithmetic. At the real 50 Hz:

- **L002 Lift** (from `SoloRoomsLayout` room 1): a full-speed cat lands on the Lift with
  **10.88 ticks** of slack before its trigger fires. D-056 (1) requires 12.
  `V3_RoomTwoLandingIsClearAndSweepRearmsVisibly`: "Expected ≥ 12.0 But was 10.8796158".
- **L004 final room** (from `SoloRoomsLayout` room 3): a full-speed cat reaches `Flip_A` while
  `Block_1` is still falling. `V3_FinalFastFlipPassesAboveTheFallingSecondBlock`: "Expected
  greater than 2.52499986 But was 1.44000006". Computed, not reached by NUnit: elapsed fall 0.75
  ticks against 6, and paw minus `Block_2` top −3.90. This is a possible unfair death in a shipped
  level.

Both tests now pin `TickTime` to 60 Hz (`// PAX-078: … Remove in PAX-078.`), so the suite is green
only because it checks the wrong rate. The generic validator catches neither gap. Only the
`SoloRoomsLayout` narrative tests see them, and they don't check L002 or L004.

**Developer's L004 report (PAX-077 §9 step 5):** Skipped by the developer; R1 is checked in §9 (R11b).
