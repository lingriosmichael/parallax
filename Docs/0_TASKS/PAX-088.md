## 1. Why

A cloud that hunts you is a different kind of pressure from every other trap: it doesn't wait for a trigger in a fixed place, it forces the player to keep moving. It still has to obey D-040: same input, same outcome, and every strike dodgeable on first sight.

## 2. What to build

1. **Element `StormCloud`** (appended). Authored pose (x, y); horizontal range `MinX..MaxX`; flies at its authored y only. **Dormant** until its trigger fires (Overlap or Chain, Once): while dormant it looks like a harmless cloud (disguise, D-056 (4)). At most one per room.
2. **Follow (pure `StormCloudMath` in Core).** Each room tick while awake and not charging: `x += clamp(catX − x, −FollowSpeed, +FollowSpeed)`, clamped to the range, using the cat's position from the previous tick's post-physics record (the same record routes read). Default `FollowSpeed` **0.08 u/tick** (4 u/s), slower than the cat's 0.12, so the player can outrun it.
3. **Strike cycle,** counted from the wake tick, every `StrikePeriod` ticks (default **100** = 2 s; first strike after `FirstStrikeDelay`, default 50):
   - **Charge (tell):** `TellTicks` (default **25**). The cloud stops, darkens, and draws a faint target line down its locked x. Harmless.
   - **Strike:** `StrikeTicks` (default 6). A lethal vertical column `StrikeWidth` wide (default 0.8) from the cloud's bottom down to the first **static** top below the locked x (a height profile baked at setup from the layout's Floor/Wall/PitBottom elements, D-059 style; no runtime raycasts).
   - Then it resumes following.
   - Kills through `RoomDeath` (`DeathCause.Hazard`) on overlap of the tick pose, like arrows.
4. **Dodge rule (fairness), validated:** `TellTicks ≥ ticksToClear + slack`, where `ticksToClear` is the ticks for a cat **at rest** under the column's centre to move its collider fully out of it (half strike width + half collider width, with the measured acceleration, D-056 (1)), and slack is 12 (8 inside a precision section, D-083). With the defaults: 0.9 u from rest ≈ 10 ticks, so ≥ 22; 25 passes.
5. **Other validator rules:** at most one cloud per room; its whole strike range (every column pose between `MinX` and `MaxX`) keeps door clearance (D-060) from the door, so reaching the door is never a lightning test; its range and y lie inside the frame; `ValidateBand`: levels 11+ only.
6. **Reset:** room reset (D-041) returns it to its authored pose, dormant. Hold and pause freeze it (room ticks).
7. **Routes.** The cloud is a killer kind the harness can name (re-run its column test). A betrayal that dies to a strike reveals by the cloud's charge (lead = strike tick − charge start ≥ 6, trivially 25). The solution must survive every strike it lives through; the route validator proves it by replay.
8. **Trap Lab room 10:** a long room with a raised middle section. Crossing the trigger wakes the cloud; the player has to keep moving and use cover (a ceiling overhang: the strike stops at the first static top, so standing under an overhang is safe). Betrayals: standing still (Dies), waiting under a fake overhang (`FakePlatform`, Dies). Solution through to the door.

## 11. Rulings (Phase 1, 2026-09-26)

**Status:** Ruled. Go to Phase 2, tests red-first. Baseline: the developer's Run All total after PAX-087 (expected 973). Where these differ from §2–§6 they amend the ticket.

**Accepted as traced:**
- **Q1:** the cloud reads the cat's `Rigidbody2D.position.x` (plus the collider's x offset) inside its room step, never the interpolated Transform. On a vine-grab tick it reads the snapped x; D-090 says so.
- **Q2:** the cloud steps in the trap loop; order among traps doesn't matter; `RoomManager.cs` unchanged.
- **Q3:** the static set is `IsFixedSolid` (Floor, Wall, PitBottom, Ceiling). Fake platforms, collapsing floors, moving Solids, falling blocks and stuck spears don't block lightning. The profile is baked on the trap as (xMin, xMax, top) segments; no physics queries at runtime.
- **Q4:** clouds are allowed in rooms with gravity flips; a cat above the cloud's bottom can't be hit. D-090 records it.
- **Q5:** the lead is measured from the cloud's first visible change, so it's at least the 25-tick charge. The room 10 camera tell test measures the rest.
- **Dodge rule:** `FromRestCrossingTicks` over half the strike width plus half the collider width, plus 12 (8 in a precision section). It replaces `ValidatePeriodicSlack` for clouds. It doesn't add to it.
- **Door clearance:** a cloud-specific check in `LevelLayoutValidator.StormCloud.cs`; `KillVolumes` and `TriggerCoverage.cs` untouched.
- **New validator clauses:** every x in `MinX..MaxX` has a static top below the cloud, and the cloud's sweep (range × its size) overlaps no static element.

### A · What stops a strike: any part of the column's width

Approved. The strike stops at the highest static top that is at or below the cloud's bottom and overlaps **any part** of the column's width. The drawn column and the lethal column always end at that same top across the full width. So a bolt is never drawn through an overhang's edge, and a cat sheltering at the edge is safe. It errs toward the player, which is right for a chasing hazard.

### B · When the cycle starts: first charge at wake + 50

Approved. Wake at tick W. The cloud follows from W+1. The first charge starts at **W + FirstStrikeDelay (50)**, so the first strike lands at W+75. After that, a charge starts every `StrikePeriod` (100) ticks, counted from the first charge. The validator requires `StrikePeriod ≥ TellTicks + StrikeTicks + 1`, so the cloud moves at least one tick between strikes. It also requires `FirstStrikeDelay ≥ 1`.

### C · The kill test: pure box math, gravity-aware

Approved: `StormCloudMath.Hits(column, catBox)`, a strict overlap (touching doesn't count), with no `Physics2D` call. The harness names the killer through the same function.
- **Build `catBox` from the body, not the Transform:** `body.position` plus the collider offset **rotated by `body.rotation`**, with the collider size. The cat's root turns 180° with gravity up (D-052), so an unrotated offset (0, −0.12) would put the box 0.24 u off for a gravity-up cat. Test: the same strike against a gravity-down cat and a gravity-up cat at the same body position gives the geometrically correct result for each (seen red with the offset unrotated).
- `Collider2D.bounds` isn't allowed here either: in Play it follows the interpolated Transform.
