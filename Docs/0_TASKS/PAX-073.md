## 1. Why

In the developer's play of L001–L004, a falling ceiling could be jumped past: the cat went
through the danger without entering the trigger, so the betrayal never fired. A trap that can be
skipped by accident isn't a troll, it's a gap in the room. The validator checks slack, reach,
reveal lead and door clearance, but nothing checks that a trigger actually catches the cat.

D-069 also needs thin, narrow floating platforms for troll-route and precision sections
(KIT-3, KIT-4). No element for them exists yet.

## 2. What to build

### 2.1 Trigger coverage rule

1. **The rule.** For every trap fired from an Overlap trigger (D-055), the cat can't reach the
   trap's danger without passing through the trigger first. "Danger" means every volume that can
   kill or betray while the trap is armed or fired: all poses and swept paths, as the kill-bounds
   and door-clearance code already computes them. "Reach" covers every approach the cat can make:
   walking in from either side, jumping (every arc the D-056 reachability model allows), falling
   in from above, and, if the room has gravity flips, the mirrored cases with gravity up.
2. **Phase 1 proposes the exact geometric check** (§3.3). My starting point is a "curtain": over
   the danger's x-span, the trigger's y-span covers the whole band the cat's collider can occupy,
   from the paw line on the highest standable surface below it up to the lower of overhead
   geometry and surface + max jump rise + cat collider height. Mirror the band for gravity up.
   Use the movement numbers the validator already uses; don't add new ones.
3. **Learned bypass.** Some triggers are meant to be avoided: jumping over them is the learned
   solution. A trap in layout data can be marked as a learned bypass with a required, non-empty
   reason string. The rule skips it, and the validator lists every learned bypass in its report
   so they stay visible. No trap in L001–L004 gets the flag unless the developer approves it by
   name.
4. **Fix the levels.** Run the rule over every `LevelLayouts` entry. Fix each failing trap by
   changing only its trigger box in the level's layout file. Each fixed layout must still pass
   every existing validator rule (slack, reach, 6-tick lead, door clearance, containment), since a
   bigger trigger can fire the trap earlier.

### 2.2 Thin platform

1. **A thin, narrow floating platform** can be authored in level layout data: plain solid
   geometry, landable from above with gravity down and from below with gravity up, with the
   ordinary floor look (D-056 (4)). If an existing element kind already expresses this with no
   builder assumption broken (§3.4), reuse it and add only validation. Otherwise add one element
   kind.
2. **Size limits** live in one config asset under `Assets/_Game/Data` (CLAUDE.md: no magic
   numbers). The validator rejects a platform thinner than the minimum thickness or narrower than
   the minimum width, naming the element. Phase 1 recommends both numbers (§3.4).
3. **No tunnelling.** At the cat's maximum fall speed, the cat must never pass through a platform
   of the minimum thickness in one physics step. Phase 1 decides whether that's guaranteed by the
   thickness minimum alone, or needs a physics setting on the cat.
4. **Not in this ticket:** one-way platforms, collapsing or fake thin platforms (KIT-3), and the
   precision-section marker (KIT-4). Thin platforms in this ticket follow D-056's reach and slack
   rules like any other geometry.

## 5. Tests (EditMode)

1. **Coverage rule, synthetic layouts:** a falling ceiling whose trigger sits at floor height
   only is rejected, naming the trap and the uncovered band; the same trap with a full curtain
   passes; approaches from the left and from the right are both checked; a gravity-up room is
   checked mirrored; a learned bypass with a reason passes and is listed; a learned bypass with
   an empty reason is rejected.
2. **Coverage rule, real levels:** every `LevelLayouts` entry passes the rule. This must fail
   first on the level with the falling ceiling.
3. **Fixed levels keep every other rule:** every `LevelLayouts` entry still passes slack, reach,
   6-tick lead, door clearance and containment. If an existing test already covers this, say
   which one and don't duplicate it.
4. **Thin platform validation:** below minimum thickness or width is rejected by name; exactly at
   the minimum passes; the limits are read from the config asset, not constants in the validator.
5. **Thin platform build:** the builder produces a solid collider with the authored size and
   position and the floor look, in both gravity directions. Building a layout that uses no thin
   platform produces the same objects as before (the existing builder and scene tests stay green).
6. **No tunnelling:** the minimum thickness is at least the worst-case travel per physics step at
   maximum fall speed, computed from `CatMotorConfig` and the fixed timestep, or the cat's
   physics setting from Phase 1 is asserted.
7. **Scenes match data:** in each listed level scene, every trap trigger's bounds equal its
   layout's. Additions to `LevelSceneTests.cs` only. Red until the developer rebuilds.

Every test must fail before the code exists, for the reason named. Mark each one "seen red"
(quote the failure) or "unproven" in the handover. No existing test is modified.

## 7. D-074 (write as built)

Every trap fired from an Overlap trigger must catch the cat before it can reach the trap's danger,
from every approach the cat can make: walking in from either side, jumping, falling in from
above, and the mirrored cases with gravity up. `LevelLayoutValidator` enforces this for every
level. A trigger meant to be avoided as the learned solution is marked as a learned bypass, with
a reason, and is listed in the validator's report. Thin, narrow floating platforms are ordinary
solid geometry with the floor look; their minimum thickness and width live in [config asset], and
the minimum thickness rules out tunnelling at the cat's maximum fall speed [or: plus the cat
physics setting from Phase 1]. [Exact coverage check from Phase 1.] [Levels and traps fixed.]
