# PAX-012 — Camera follow with dead zone (world-aligned)

**Phase:** 2 — One ugly cat
**Test scope:** Editor (device verification happens at Gate 2)
**Depends on:** PAX-006, PAX-007, PAX-008, PAX-010, PAX-011
**Reviewer pass required:** No (no networking, no shared state)

---

## CONTEXT

`02_ARCHITECTURE.md` §3.2 (Cameras). Decision **D-020**: the camera stays world-aligned
and never rotates with gravity. This resolves open question Q-2.

The camera must survive two things the sandbox already does:

1. **Gravity rotation (PAX-010).** When gravity points right, the cat walks up what looks
   like a wall. The camera must follow that vertical movement without rotating.
2. **Respawn (PAX-011).** `CatRespawn` teleports the cat. Without an explicit snap, the
   camera smooth-follows across the whole arena, which looks broken and hides the reset.

This camera is written so it can later be instantiated twice — one per Observer (PAX-016).
It therefore takes its target as a serialized reference and must not use `Camera.main`,
`FindObjectOfType`, or any singleton lookup at runtime.

### `CameraMath` (Parallax.Core — pure, no UnityEngine dependencies beyond `Vector2`)

```csharp
public static class CameraMath
{
    /// Returns the camera centre required to keep `target` inside a dead-zone
    /// rectangle of half-size `halfExtents` around `currentCentre`.
    /// If the target is already inside the rectangle, returns `currentCentre` unchanged.
    public static Vector2 ResolveDeadZone(Vector2 currentCentre, Vector2 target, Vector2 halfExtents);

    /// Clamps a camera centre so the visible rectangle (halfWidth × halfHeight)
    /// stays inside `boundsMin`..`boundsMax`. If the bounds are smaller than the
    /// view on an axis, the camera centres on the bounds on that axis.
    public static Vector2 ClampToBounds(Vector2 centre, Vector2 halfView, Vector2 boundsMin, Vector2 boundsMax);
}
```

Each axis is resolved independently. This is the whole reason the maths lives in Core:
it is testable without a scene.

### `CatCameraFollow` (Parallax.Gameplay)

Serialized fields:

| Field | Default | Notes |
|---|---|---|
| `Transform target` | none | The cat. Assigned in the Editor, never looked up. |
| `Vector2 deadZoneHalfExtents` | `(2.0, 1.6)` | World units. Tall enough that a normal jump does not scroll the view. |
| `float smoothTime` | `0.18` | Passed to `Vector2.SmoothDamp`. |
| `float maxSpeed` | `40` | SmoothDamp clamp, so a fast fall cannot outrun the camera. |
| `bool useBounds` | `false` | Off by default in the sandbox. |
| `Vector2 boundsMin` / `boundsMax` | `(0,0)` | Only read when `useBounds` is true. |
| `CatRespawn respawn` | none | Optional. If assigned, the camera snaps on its event. |

Behaviour:

- Runs in **`LateUpdate`**, reading the target's current position after physics has settled.
- Computes the desired centre with `CameraMath.ResolveDeadZone`, smooths toward it with
  `Vector2.SmoothDamp`, then applies `ClampToBounds` if `useBounds` is true.
- **Z is preserved.** Only X and Y are written. Never touch `transform.rotation`.
- `public void SnapToTarget()` — sets the centre to the target position immediately,
  zeroes the SmoothDamp velocity, and applies bounds clamping. Called on respawn.
- Subscribes to `CatRespawn.Respawned` in `OnEnable`, unsubscribes in `OnDisable`.
  Null reference is fine and must not throw.
- `Start` calls `SnapToTarget()` so the first frame is already framed correctly.
- `OnDrawGizmosSelected` draws the dead-zone rectangle, and the bounds rectangle when
  `useBounds` is true. This is the tuning tool — do not skip it.

### `CatRespawn` modification

Add `public event System.Action Respawned;` and raise it after the position and motion
reset completes. **No other change to that file.** Do not reorder or alter the existing
reset logic.

### `CameraSetup` (Editor)

Menu item `PARALLAX/Setup/Configure Camera Follow`, idempotent:

1. Find the scene's main camera. If it is not orthographic, log a clear error and stop.
2. Add `CatCameraFollow` if absent. Never add a second one.
3. Assign `target` to the `Cat_Player` instance's transform (the root, not the Visual child).
4. Assign `respawn` to the `CatRespawn` on that same instance if one exists.
5. Log exactly what was assigned or what was already correct, and mark the scene dirty
   only when something actually changed.

### Tests (`CameraMathTests`, EditMode)

At minimum:

- Target inside the dead zone returns the centre unchanged.
- Target past the right edge pushes the centre right by exactly the overshoot.
- Target past the bottom edge moves Y only, leaving X untouched.
- `ClampToBounds` with a view larger than the bounds centres on the bounds.

All existing tests must still pass. Total should be 14 or more.

## ACCEPTANCE TEST (Editor)

1. Press Play. The cat is framed on the first frame — no visible glide into position.
2. Move with A/D inside the dead zone. The camera does not move at all.
3. Keep moving past the dead-zone edge. The camera follows smoothly and the cat stays
   roughly at that edge. Reverse direction: the cat crosses the dead zone before the
   camera starts moving again.
4. Jump repeatedly on flat ground. The camera does **not** bob vertically.
5. Press E to rotate gravity so the cat falls right. Walk up the wall. The camera
   follows vertically and **does not rotate** — the ground stays horizontal on screen.
6. Repeat for all four gravity directions. No rotation in any of them.
7. Walk into the `FallResetTest` volume. The camera snaps instantly to the spawn point.
   There is no sweep across the arena.
8. Tick `useBounds`, set a small rectangle around the ground, and walk to the edge.
   The camera stops; the cat continues to the screen edge.
9. Run all EditMode tests. 14 or more pass, zero fail.
10. No Console errors or new warnings.
