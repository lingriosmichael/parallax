## 1. Why

Levels 11+ get five new mechanics (KIT-5–KIT-9). The spear is the cheapest and reuses most of the kit: an arrow that flies extremely fast, **once**, and then stays stuck in the wall as a mini platform the cat can stand on and jump from. It gives a room two lives: first the spear is the threat, then it's the staircase.

## 2. What to build

1. **A spear variant of the arrow.** `ArrowLane` gains `bool Spear` (optional last constructor parameter, default false) plus `float PlatformThickness` (default 0.25). A spear:
   - has the arrow's three phases (D-078): **tell** (visible at the mouth, harmless, ≥ 6 ticks), **flight** (lethal, constant speed, pure function of ticks since fire), **stop** at the lane's authored end face;
   - is **Once only**: Rearm and Periodic are validator errors for spears ("fires once per room life", D-051);
   - on the first tick after the stop tick becomes **solid geometry**: its shaft (Length × PlatformThickness, top flush with the visual shaft's top) gets a non-trigger `BoxCollider2D` on the room's floor layer, so the motor's ground cast stands on it and the cat can jump from it (coyote and buffer as on any floor). The stop tick itself is still lethal (last flight pose);
   - is never lethal once stuck; its tip reads as embedded in the end face;
   - resets with the room (D-041): back in the launcher, unfired, collider off.
2. **"Extremely fast" inside the no-tunnelling cap.** D-078's cap is v ≤ Length + (collider width − collider height) − 2 × run per tick. Spear defaults: Length 1.4, speed **1.2 u/tick** (60 u/s; the cap at 1.4 is 1.40). The tell stays ≥ 6 ticks (D-057), default 8.
3. **Validator rules** (separately named, never inside `Validate`):
   - `ValidateSpear`: Once only; Length ≥ `PlatformSizeConfig` min width (1.0) so the stuck spear is standable; the end face belongs to fixed geometry (a Wall/Floor/Ceiling element), never a moving Solid, `CollapsingFloor` or `FakePlatform`; the stuck shaft overlaps no other element; `PlatformThickness` ≥ 0.2.
   - The existing arrow rules (tell, speed, lane, door clearance, coverage) apply to spears unchanged.
   - `ValidateReach` may treat a stuck spear as a landing only for a `RequiredJump` marked `AfterFire` (new optional flag); the route validator proves the order (the solution route must fire the spear before it lands on it).
   - `ValidateBand` (D-083 (4)): a spear in a level numbered 1–10 is an error naming the level. **This ticket turns `ValidateBand` into the shared "levels 11+ only" check** that KIT-6–KIT-9 extend with their kinds.
4. **Routes.** `RouteValidator` names a spear kill with the arrow's kill test; the stuck spear is plain geometry to the harness. Add a route condition `Fired(name)` if Phase 1 finds none exists.
5. **Trap Lab room 6** (next free origin after room 5): a shaft with a high exit ledge. Crossing a trigger fires three spears into the far wall at rising heights; once stuck they're the stairs to the door. Betrayals: standing in a lane (Dies, lead ≥ 6); jumping to the ledge before firing the spears (Recovers or Dies in a pit, whichever the layout gives). Routes in `TrapLabRoutes.Room6`.

### R1 · Thickness: the collider is the visible shaft, with its own spear minimum

- The shaft collider = the visible shaft, `Length × Thickness` (the lane's existing `Thickness`). **Drop `PlatformThickness`.** One size, one source.
- Don't force 0.5. A 0.5-thick spear is almost as tall as the cat (0.56) and reads as a log, not a spear. Instead, `PlatformSizeConfig` gains `spearMinThickness`, default **0.4**, and `ValidateSpear` checks it. That's one max-fall tick (20 u/s × 0.02 s), so D-074 (6)'s tunnelling argument holds on its own, even before the Continuous body and the ground cast. Floors keep 0.5. Spear default `Thickness` 0.4.
- Width: `Length ≥ PlatformSizeConfig.MinWidth` (1.0), as the ticket says.
- The Phase 2 drop test runs at max fall onto a 0.4 shaft. If it tunnels, stop and report; don't raise the number yourself.
- Record the new field in D-086 as an amendment to D-074 (6), for spears only.

### R2 · The tick after the stop: kill, with a strict overlap

Approved. On the first tick after the stop, before the collider switches on, the spear checks the cat against the shaft box **shrunk by 0.02 per side** (the same shrink `FallingBlock` uses; it keeps Box2D's ~0.01 contact skin from counting). If they overlap, that's a kill through `RoomDeath` (`DeathCause.Hazard`), and the collider stays off for the death hold. Otherwise the collider switches on and the spear stays harmless until reset.
- So a spear is lethal on its flight ticks, on the stop tick, and for this one check on stop + 1. `ArrowMath.IsLethal` (or the spear's own branch) says so, and the route harness uses the same function (R3).
- A collider that stays off "until the cat clears it" is rejected: a platform that is sometimes solid and sometimes not is exactly the unreadable state this game avoids.
- Test: a cat that walks into the final spot during the stop tick's physics step dies on stop + 1, named as the spear (seen red).

### R3 · Allowed list: `RouteReplay.cs` and `SpearFixtures.cs` added

- **`RouteReplay.cs` approved.** Killer naming counts an arrow only on ticks where it's lethal, from the same function the runtime uses (fire + tell through the stop tick, plus R2's stop + 1 for spears), not "visible and overlapping". **Apply it to all arrows**: a stopped arrow is harmless by D-078, so naming it was always wrong, just never exercised.
- Guard: every pinned route result (`ShippedRouteResultsTests`, Trap Lab 3–5 routes, the camera tell results, the L001–L010 routes) must be **identical** after the change. If any pin moves, stop and report; don't re-pin.
- Test: a cat standing on a stuck spear, killed by a second spear in a higher lane, is named as the second spear, not ambiguous (seen red before the fix).
- **`SpearFixtures.cs` approved** next to `ArrowFixtures.cs` in `Editor/Setup/`, the existing convention. Test-only content; no runtime code reads it.

### R4 · `AfterFire`: dropped

Approved. The solution route proves the order (no collider before the fire, so an early landing fails the replay). Declare the jumps onto stuck spears as ordinary `RequiredJump`s so reach is still checked (0.75 in levels, band thresholds inside precision sections). `RequiredJump` doesn't change.

### R5 · Speed cap: arithmetic, still measured

At the committed collider (1.0 × 0.56), D-078's cap at length 1.4 is 1.4 + 0.44 − 0.24 = **1.60 u/tick**, so 1.2 fits with room. Phase 2 reads the collider from `CatMotorConfig` and asserts it in the speed test; nothing else to decide.
