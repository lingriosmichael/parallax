# PAX-052 · Single-room camera framing

**Status:** Approved for implementation once PAX-051 is committed
**Phase:** Solo v1, Phase B
**Depends on:** PAX-051
**Decisions:** D-062 (one screen or close to it), D-020 (world-aligned), D-064
**Implementer reads first:** `CameraMath`, `CatCameraFollow`, `CameraSetup`, `LevelLayout`,
`RoomManager` kill bounds, the level template setup from PAX-051.

---

## 1. Why

A one-room level should be seen whole, like Level Devil: the player reads the room before
moving. The current follow camera (PAX-012) was built for multi-room walks. The target phone is
20:9; other Android phones run from 16:9 to about 21:9.

## 2. What to build

1. **`LevelLayout.ViewRect`**: the world rect the player must see (defaults to the room's
   geometry bounds without the kill margin; editable per level).
2. **`RoomFraming`** (`Parallax.Core`, pure): given the view rect, screen aspect, a padding and
   `minOrthoSize`/`maxOrthoSize`, returns the orthographic size and camera centre that fit the
   whole rect. If the rect needs a size above `maxOrthoSize`, it returns `maxOrthoSize` and
   a clamp rect for following.
3. **`RoomCameraFraming`** (`Parallax.Gameplay`): on scene start and when the screen size
   changes, applies `RoomFraming`. Static when the room fits; otherwise follows the cat, clamped
   to the view rect, reusing `CameraMath`'s clamp-before-SmoothDamp rule. Camera never rotates
   (D-020).
4. **`CameraFramingConfig`** (`Assets/_Game/Data`): padding, min/max ortho size, and a
   `bottomControlInset` (fraction of screen height kept clear for the stick/jump buttons,
   default 0: decide on device in Phase H).
5. The level template (PAX-051) uses `RoomCameraFraming` instead of `CatCameraFollow`.
   `Rebuild All Levels` updates L001–L004. `CatCameraFollow` stays for other scenes.

## 3. Phase 1 — as-built trace

1. Which component sets the camera's ortho size today, and where is the value stored?
2. Is anything else (HUD, touch regions) positioned relative to camera size?

## 4. Rules

- Pure math in Core; no `UnityEngine.Camera` in Core.
- No per-level camera tweaks in scenes; the only per-level input is `ViewRect` in data.
- `Level_Solo01`, `Sandbox_*` scenes unchanged.

## 5. Tests (EditMode)

1. A rect that fits at 16:9 and 21:9 is fully inside the camera view at both aspects.
2. Centre equals the rect centre when it fits.
3. A rect wider than `maxOrthoSize` allows returns `maxOrthoSize` and a follow clamp rect.
4. Framing is identical for gravity up and down (no rotation input exists).
5. Every listed level's `ViewRect` fits at 20:9 without follow (warn-level check that prints
   the levels that need follow, fails only if `ViewRect` is empty).

## 6. Allowed files

New files under `Core`, `Gameplay`, `Data`, `Editor/Setup`, `Tests/EditMode`; `LevelLayout.cs`;
the PAX-051 template/rebuild setup script; level scenes via menu only.

## 7. Out of scope

Camera shake or juice · safe-area UI layout (PAX-053/054) · device check (Phase H).
